Summer is the game engine built for AI. Everything your agent can do with Summer is an operation: one name such as `assets.generate_3d` or `store.publish`, one input, one answer. The hosted MCP, the npm MCP and the `summer` CLI all run the same 386 operations: 284 on Summer's servers and 102 on your computer.

<Note>
Generated from the `summer-engine` npm package `4.8.0`: its public operation catalog (`registry/operations/public-catalog.json`) and its engine and local operations. If something here is wrong, the operation's definition is wrong.
</Note>

## Call an operation

| From | How |
|---|---|
| Hosted MCP, `https://mcp.summerengine.com/mcp` | The common jobs are their own tools (below). For anything else, `summer_search` finds the operation from the job in plain words and returns its exact input. Then `summer_call` runs it: `{"op": "pricing.set_base", "input": {...}}`. |
| npm MCP, `summer mcp` | Engine operations under their tool names, such as `summer_add_node` and `summer_play`, plus `summer_search` and `summer_call`. After `summer login` it runs every cloud operation too. |
| CLI | `summer <area> <action> --field value`, for example `summer assets search --query knight`. Add `--dry-run`, `--wait` or `--json`. `summer ops search <words>` finds an operation; `summer ops describe <name>` prints its input. |

## The answer

Every operation answers one JSON shape. MCP sends it as text and as structured content; the CLI prints it with `--json`.

| `status` | Means | What the agent does next |
|---|---|---|
| `done` | Finished. `result` holds the answer. | Use `result`. |
| `running` | Long work started. `job.id` names it. | Call `jobs.wait` with the job id until it is done. |
| `needs_approval` | The change waits for your yes. Nothing has changed. | Give you `approval.url`, then call `jobs.wait` with the job id. |
| `dry_run` | A check only (`dryRun: true`). Nothing changed and nothing was spent. | Read `preview`: the changes, and for spend operations your estimated credits. |

An error answers `ok: false` with `error.code`, a plain `message`, exactly one `next` step and `retry` (`no`, `safe`, `same_key` or `after`).

Every operation that changes something also takes:

- `dryRun: true` to check the call and see what it would do. Nothing changes, nothing is spent and nothing is sent.
- `idempotencyKey` to retry safely: the same key with the same input gives the first answer again and never does the work twice. Operations that go live or move money require it.

## What your agent may do without asking

Studio shows six switches in **Settings > Agent permissions**. They apply to every app you connect. These defaults apply now. You can change them soon. Until then, Summer Games still asks the game's owner before an agent publishes, and price, A/B test and member changes ask you first. When a change asks, the operation answers `needs_approval` with a link, and your open Studio tab shows the request. Nothing changes until you approve. **Settings > Agent activity** lists what your agents did, with Undo for prices, sales, member roles, team names and the event limit.

| Permission | By default | Operations |
|---|---|---|
| Make and build | On: runs at once | 155 |
| Spend credits | On: runs at once | 53 |
| Publish | On: runs at once, except what Summer Games still asks for | 10 |
| Prices and live changes | On: runs at once, except what Summer Games still asks for | 10 |
| Delete for good | Off: asks you first | 20 |
| Contact people | Off: asks you first | 5 |
| Always asks | You approve each time | 8 |
| Reads | Never ask | 125 |

Spending never asks per call: agents spend within your credits and the monthly limit of your auto top-up. When credits run out, the answer is `no_credits` with a link to add credits.

## Errors

The list is closed: a new code is a new version of the catalog.

| `code` | When | `retry` |
|---|---|---|
| `invalid_input` | The input does not match the operation. details.path names the field. | `no` |
| `not_signed_in` | The operation needs a Summer sign-in and there is none. | `no` |
| `forbidden` | Signed in, but not allowed: not your game, or not a member. | `no` |
| `not_found` | The target does not exist or has expired. | `no` |
| `conflict` | The thing changed since it was read. Read it again, then retry. | `no` |
| `idempotency_conflict` | The same idempotencyKey was used with a different input. | `no` |
| `in_progress` | The first call with this idempotencyKey is still running. | `after` |
| `rate_limited` | Too many calls. details.retryAfterSeconds says when to try again. | `after` |
| `no_credits` | Not enough credits for this call. | `no` |
| `over_limit` | A limit was reached: a plan or allowance limit, or the spend limit the person set for this app. | `no` |
| `engine_not_running` | An engine operation was called and no Summer Engine is open. | `safe` |
| `engine_lacks_op` | The open Summer Engine is too old for this operation. | `no` |
| `unsupported` | This server cannot run the operation (an engine operation on the hosted server). | `no` |
| `not_in_profile` | The operation exists, but this server version does not serve it. | `no` |
| `moved` | A 3.x tool was called with arguments that now belong to another operation. next has the exact new call. | `no` |
| `outcome_unknown` | The call may or may not have happened. Check with the read in next before retrying with the same key. | `same_key` |
| `unavailable` | A Summer service is down for a moment. | `after` |
| `internal` | A bug on Summer's side. The answer has a requestId for support. | `no` |
