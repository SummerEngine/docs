Any AI agent can build, test and publish a Summer game. Three pieces make that work, and one command sets up all three:

- **The Summer MCP server** gives your agent Summer's tools: build scenes, play the game, take screenshots, make assets, publish.
- **The `summer` command** runs the same operations from a shell, for agents that prefer commands and for your own scripts.
- **Summer skills** are short guides your agent reads when a task matches, such as `multiplayer-project` or `publish-your-game`, so it builds the good version on the first try.

```bash
npx -y summer-engine@latest setup <agent> --yes
```

Replace `<agent>` with `claude-code`, `codex`, `cursor` or [your agent's id](/mcp/setup#every-agent). New here? Follow [Quickstart: coding agent](/quickstarts/coding-agent).

## Which one do I use?

| You use | Set up | Your agent can |
|---|---|---|
| A coding agent with a terminal: Claude Code, Codex, Cursor, VS Code and 27 more | `npx -y summer-engine@latest setup <agent> --yes` | Everything: drive Summer Engine on your computer, plus every cloud operation after `summer login` |
| A chat app: Claude, ChatGPT, Claude Desktop | Add `https://mcp.summerengine.com/mcp` as a connector | Cloud work: assets, plans, the store page, publishing, prices, analytics |
| A script or CI job | The `summer` command, see [CLI](/mcp/cli) | Any operation: `summer <area> <action>` |
| An agent with a tool limit | `setup <agent> --profile engine`, or `--cli` for no MCP server | The engine tools only, or the shell only |

## Local and hosted MCP

| | Local server | Hosted server |
|---|---|---|
| Runs | On your computer: `npx -y summer-engine@latest mcp` | At `https://mcp.summerengine.com/mcp` |
| Engine work: scenes, scripts, play, screenshots | Yes | No |
| Cloud work: assets, store, publishing, analytics | Yes, after `summer login` | Yes |
| Sign-in | Engine work needs none. `summer login` once for cloud work | Once in the browser when you connect (OAuth) |
| Needs | Node.js 22 or newer, and Summer Engine for engine work | Nothing to install |

One local server is enough: after you sign in, it also runs every cloud operation. The setup command writes it for you. Your agent opens your project in Summer Engine by itself when it needs the engine.

## What your agent can do

| Area | For example |
|---|---|
| Scene and project | Add nodes, set properties, save scenes, change project settings and input |
| Play and check | Play the game, read errors, take screenshots of the running game, Local Play with several players |
| Files | Read, write and patch scripts and resources in the open project |
| Assets | Search the asset library, generate images, 3D models, sound, music and video |
| Publish and grow | Create the game on Summer Games, fill the store page, upload builds, go live, read analytics |
| Everything else | `summer_search` finds the operation for a job in plain words; `summer_call` runs it |

Every operation, its input and its answer: [Operations](/mcp/operations). How answers, errors and jobs work: [How Summer answers](/api-reference/mcp).

## You stay in control

Your agent asks you before anything that costs money, changes what players see, or can't be undone. **Studio > Settings > Agent permissions** sets what agents may do on your account. Building and spending credits are on by default; deleting for good and contacting people are off. When an action needs your yes, the agent gets a link to an approval page in Studio and passes it to you.
