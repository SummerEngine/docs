## Summer Engine in OpenCode

OpenCode is an open-source terminal agent that supports MCP (Model Context Protocol). With Summer Engine's integration, OpenCode can control your game engine: add nodes to scenes, set properties, search and import assets, generate images and 3D models, run the game, and debug, all from the terminal.

This guide covers the configuration. Setup takes about a minute.

## Prerequisites

- **OpenCode**: The open-source terminal agent
- **Node.js 20+**: For running the MCP server
- **Summer Engine**: Open with your project, for engine work only
- **Sign in once**: `npx -y summer-engine@latest login`. One browser sign-in also connects the store, publishing and Grow tools

## Configuration

### Option 1: One-command setup (recommended)

Run the Summer setup command. It writes the OpenCode config, installs the Summer skill library to `~/.agents/skills`, and runs diagnostics:

```bash
npx -y summer-engine@latest setup opencode --yes
```

This writes to your user OpenCode config (`~/.config/opencode/opencode.json` on macOS and Linux, `%APPDATA%\opencode\opencode.json` on Windows). For a single project, use `--scope project` to write `opencode.json` in the project root instead.

### Option 2: Manual configuration

Create or edit your OpenCode config and add the `summer-engine` MCP server. OpenCode uses a `command` array and an `environment` object:

<CodeGroup>

```json New file (opencode.json)
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "summer-engine": {
      "type": "local",
      "command": ["npx", "-y", "summer-engine@latest", "mcp"]
    }
  }
}
```

```json Adding to existing mcp
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "other-server": { ... },
    "summer-engine": {
      "type": "local",
      "command": ["npx", "-y", "summer-engine@latest", "mcp"]
    }
  }
}
```

</CodeGroup>

To preview the exact config without writing files, run:

```bash
npx -y summer-engine@latest setup opencode --print
```

### Restart OpenCode

Close and restart OpenCode so it loads the new config. The Summer Engine MCP server starts with OpenCode; it connects to the engine on the first tool call.

### Verify

List your MCP servers in OpenCode and confirm `summer-engine` appears with its tools. Then try a prompt:

- "Use Summer Engine to add a MeshInstance3D with a BoxMesh to the scene"

If the node appears in Summer Engine, the setup is working.

## Using Summer Engine with OpenCode

Once configured, OpenCode can use Summer Engine's tools when you ask for game-related changes. Example prompts:

- "Add a Camera3D and DirectionalLight3D to the scene root"
- "Get the scene tree from Summer Engine"
- "Generate a low-poly treasure chest and import it under the World node"
- "Run the game and read the diagnostics"
- "Set the project's main scene to res://main.tscn"

<Tip>
**Engine tools need the engine.** Open your project in Summer Engine first, or run `npx summer-engine run` from the project directory. Asset, plan, store and publishing tools do not need it.
</Tip>

## Troubleshooting

### "Summer Engine is not running" (`engine_not_running`)

Start Summer Engine and open your project. The MCP server connects to the engine's local API on port 6550. The engine writes a token to `~/.summer/api-token` when it starts.

Every Summer error names its code and one next step (`next`). `not_signed_in`: run `npx -y summer-engine@latest login`. `no_credits`: add credits at `https://www.summerengine.com/studio/credits`. All codes: [How Summer answers](/api-reference/mcp#errors).

### MCP server not appearing

- **Config path:** Verify the config exists at `~/.config/opencode/opencode.json` (or `opencode.json` in the project root for project scope)
- **JSON validity:** Ensure no trailing commas and valid JSON
- **Restart:** Fully quit and reopen OpenCode
- **Diagnostics:** Run `npx -y summer-engine@latest doctor` to check the MCP server boot, login, and engine connection

### Tools return errors

See [Value formats](/mcp/operations/engine#value-formats) for parameter formats. Common issues: wrong node path format (`./World/Player`), invalid property values (use engine string format like `"Vector3(0, 10, 0)"`), or the game running when scene edits are attempted (stop it first with `summer_stop`).
