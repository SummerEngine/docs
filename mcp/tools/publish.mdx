### summer_build_begin_upload

On the hosted MCP.

Start uploading an exported game build (the summer.games .zip bundle or one .pck) to a store game: the same build-publication steps as Studio upload. Returns publicationId and the part plan (64 MiB parts). Then hash each part, call [`summer_build_sign_parts`](/mcp/tools/publish#summer_build_sign_parts), PUT each part to its URL with every returned header, and finish with [`summer_build_complete_upload`](/mcp/tools/publish#summer_build_complete_upload). The local summer-engine MCP does all of this from disk ([`summer_publish_build`](/mcp/tools/publish#summer_publish_build)). Calling again for the same file resumes.

### summer_export_game

On the local MCP (`summer-engine` npm).

Export the game in the exact file the Summer Games store takes, with the installed Summer Engine headless (no window). format "bundle" (default): the summer.games .zip the Summer apps run on iPhone, Android, macOS and Windows; targets picks the platforms (a game without a server: ios and android only); upload it with [`summer_publish_build`](/mcp/tools/publish#summer_publish_build). format "download" with one target: web (an HTML5 .zip on Summer's WebGPU Forward+ web template, played on summer.games), macos (.app zip, macos-universal) or windows (.exe zip, windows-x64); these need the export template from [`summer_export_templates`](/mcp/tools/publish#summer_export_templates) and are uploaded as store versions. Works without the editor running. Returns path, sha256, size, the manifest or store platform, and warnings.

| | |
|---|---|
| **Needs** | No open editor and no sign-in |
| **Effects** | writes files |
| **CLI** | `summer tool export-game --args '<json>'` |

**Use when:**

- "export my game for summer.games"
- "make a build I can upload to my store page"
- "export my game for iPhone and Android on Summer Games"
- "make a web build of my game for summer.games"
- "export a Mac or Windows download for my store page"
- preparing the bundle that [`summer_publish_build`](/mcp/tools/publish#summer_publish_build) uploads

**Do not use when:**

- exporting for Steam, itch.io, the App Store, Google Play or other stores — skill/export-and-ship
- the game is still being built; export when the user wants a Build

### summer_store_version_begin_upload

On the hosted MCP.

Start uploading a web build or a desktop download to a store game ([`summer_export_game`](/mcp/tools/publish#summer_export_game) with format "download" makes these). web: a .zip with index.html at its root (at most 500 MiB, 2000 files), played on summer.games in a frame. macos-universal, windows-x64, linux-x64: the archive players download (at most 20 GiB). Returns versionId and the part plan; then [`summer_store_version_sign_parts`](/mcp/tools/publish#summer_store_version_sign_parts), PUT each part, [`summer_store_version_complete`](/mcp/tools/publish#summer_store_version_complete). The local summer-engine MCP does all of this from disk.

| | |
|---|---|
| **Needs** | Your Summer account (OAuth). In the npm MCP: `summer login --store` |

**Inputs:**

| Input | Type | Required | Description |
|---|---|---|---|
| `gameId` | string | Yes |  |
| `platform` | "web" \| "windows-x64" \| "macos-universal" \| "linux-x64" | Yes |  |
| `fileName` | string | Yes | Length 1 to 255. |
| `sizeBytes` | integer | Yes | Range 1 to 9007199254740991. |
| `label` | string | No | A version label players may see, e.g. 1.0.2. Default `""`. Length 0 to 80. |
