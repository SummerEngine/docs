## What is the CLI?

The Summer Engine CLI lets you install the engine, create projects, run the engine, and connect your AI IDE (Claude Code, Cursor, Devin Desktop) to Summer Engine. Add the MCP config to your IDE and it will spawn the MCP server. You chat with the AI in your IDE, and the AI uses MCP tools to manipulate scenes, run the game, and debug.

Use `npx summer-engine` (no install) or `summer` (after global install).

## Install the Engine

```bash
npx summer-engine install
```

Downloads and installs Summer Engine to your system (macOS: `/Applications/Summer.app`, Windows: default location). No npm global install required.

## Sign In

```bash
npx summer-engine login
```

Opens your browser once. You sign in to your Summer account with Google, GitHub, or email, then approve the store, publishing and Grow tools in the same browser. If that second step does not finish, run `summer login --store`.

## Create a Project

```bash
npx summer-engine create 3d-basic my-game
```

Creates a new project from a template. Templates: `empty` (minimal 3D) or `3d-basic` (camera, light, floor).

## Run the Engine

```bash
npx summer-engine run my-game
```

Launches Summer Engine with your project. Engine tools need the engine running with your project. Cloud operations (assets, plans, the store, prices, analytics) do not.

## Start MCP (for Cursor, Claude Code, Devin Desktop)

One command writes the MCP config for your agent and installs the Summer skills:

```bash
npx -y summer-engine@latest setup <agent> --yes
```

The agent spawns `summer mcp` when it connects. You don't run it manually. To edit the config by hand, add this to your agent's MCP config:

```json
{
  "mcpServers": {
    "summer-engine": {
      "command": "npx",
      "args": ["-y", "summer-engine@latest", "mcp"]
    }
  }
}
```

See [MCP setup](/mcp/setup) for each agent. For cloud work only (assets, plans, the store, publishing), you can skip the install and add `https://mcp.summerengine.com/mcp` to your agent instead.

## Run Summer Operations from the Shell

Every Summer operation runs from the shell, with the same answer as in the MCP:

```bash
summer whoami                                   # Who is signed in, plan and credits
summer ops search put my game on sale           # Find the operation for a job
summer ops describe pricing.schedule_discount   # Its exact input
summer games list --json                        # Run one: summer <area> <action>
```

Add `--dry-run` to check a change first, `--wait` to follow a job or an approval, and `--json` for the answer only. Exit code `0` means an ok answer, `1` an error. Details: [Operations from the shell](/mcp/cli-reference#operations-from-the-shell).

## Full CLI Reference

| Command | Description |
|---------|-------------|
| `summer setup <agent> --yes` | Configure your agent's MCP, install the Summer skills, run diagnostics |
| `summer doctor` | Check Node, the CLI, skills, sign-in, the engine and the MCP server |
| `summer install` | Download and install Summer Engine |
| `summer login` | Sign in via browser |
| `summer whoami` | Who is signed in, plan and credits |
| `summer logout` | Clear auth tokens |
| `summer status` | Check engine status, port, auth |
| `summer run [path]` | Launch engine, optionally with project |
| `summer open <path>` | Open project in running engine |
| `summer create <template> [name]` | Create project from template |
| `summer list templates` | Show available templates |
| `summer list projects` | Show projects in current directory |
| `summer skills list` | List available skills |
| `summer skills install <name> --agent <agent>` | Install a skill where that agent reads skills |
| `summer mcp` | Start MCP server (used by IDEs) |
| `summer tool <name>` | Run one Summer tool by its slug or MCP name |
| `summer <area> <action>` | Run any Summer operation |
| `summer ops search <words>` | Find the operation for a job |
