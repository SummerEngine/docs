Summer is the game engine built for AI. There is no separate chat API. Your own agent talks to Summer through the **Summer MCP** (Model Context Protocol), with the same operations everywhere.

## Two servers, one set of operations

| | Hosted MCP | Local MCP |
|---|---|---|
| Address or command | `https://mcp.summerengine.com/mcp` | `npx -y summer-engine@latest setup <agent> --yes` writes `summer mcp` into your agent |
| Does | Assets, plans, the store, publishing, prices, analytics | The engine: scenes, scripts, play, screenshots, errors. After `summer login`, also every cloud operation |
| Works in | Claude and ChatGPT (web, desktop and phone), Claude Code, Codex, Cursor and any MCP app with OAuth | Claude Code, Codex, Cursor, Devin Desktop, Antigravity, VS Code, Zed and [many more](/mcp/agents) |

## How the local server reaches the engine

1. Summer Engine runs a local API on `localhost:6550` while a project is open. If that port is busy, it picks another and writes it to `~/.summer/api-port`.
2. The engine writes a token to `~/.summer/api-token` on every start. The local MCP reads it. You manage no keys.
3. Your agent calls a tool, and the change appears in the editor.

Cloud operations need your Summer sign-in. See [Authentication](/api-reference/authentication).

## Example: add a node

When you ask your agent "Add a Camera3D to the scene", it calls:

```
summer_add_node(scenePath="res://main.tscn", parent="./", type="Camera3D", name="MainCamera")
```

The node appears in Summer Engine at once. Every call answers in one shape: [How Summer answers](/api-reference/mcp).
