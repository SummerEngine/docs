**Class:** `SummerMatchResult` · **Inherits:** RefCounted

This player's own view of one concluded Match.

Two facts converge in one object and nothing else does. When the authority's settlement commits, the Engine delivers to exactly this Session its [`outcome`](/api-reference/gdscript/types/match-result#outcome), with [`rating_state`](/api-reference/gdscript/types/match-result#rating_state) at [`RATING_STATE_PENDING`](/api-reference/gdscript/types/match-result#rating_state_pending) and no rating values: the authority never relays account data. Later the platform commits this player's rating and delivers it privately through the trusted Player Host; the same object then carries [`rating`](/api-reference/gdscript/types/match-result#rating) and moves to [`RATING_STATE_COMMITTED`](/api-reference/gdscript/types/match-result#rating_state_committed). Queues without a rating stay at [`RATING_STATE_NONE`](/api-reference/gdscript/types/match-result#rating_state_none).
The object is keyed by [`match_id`](/api-reference/gdscript/types/match-result#match_id) and [`session_id`](/api-reference/gdscript/types/match-result#session_id). A rating fact for another Match or Session never touches it, and a replayed or older fact is ignored: only a strictly newer [`SummerRatingSnapshot.version`](/api-reference/gdscript/types/rating-snapshot#version) on [`SummerRatingChange.after`](/api-reference/gdscript/types/rating-change#after) is applied.
