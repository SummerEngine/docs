## summer-engine 4.8: the Summer API, Studio inside the Summer app, and agents that show their work

Released on npm as `summer-engine@4.8.0`. Version 4.7.0 was not published; its changes ship here.

- **The Summer API from your agent.** `summer api models`, `estimate`, `run` and `jobs`, and the `summer_api_*` MCP tools, make images, 3D models, sound and video with Summer's curated models. They use your Summer sign-in, with no API keys to copy. `summer api run --batch` queues up to 500 jobs at once.
- **Agents show you what they work on.** `summer_view_set` moves the Summer app to the view the agent is working in: chat, 3D, 2D, script, game or Studio.
- **Studio opens inside the Summer app.** Studio pages and forms run in the app's own Studio tab when it is open, instead of a browser.
- **Signed out? One link.** A cloud tool that needs the Summer sign-in answers with a sign-in link, and the next call works once you sign in.
- **Opening a project switches the running editor** to it in the same window.
- **Summer Radio for agents** (`studio.radio`), **`summer token`** for curl, and the **Summer Router** commands and skill (early preview).
- Node.js 22 or newer.

</Update>

## summer-engine 4.5: from nothing to a live game over MCP

Released on npm as `summer-engine@4.5.0`. Version 4.4.0 was not published; its changes ship here.

- **`summer dev`**: one command installs Summer Engine (with your yes), creates a good-looking starter project and opens it for your agent. Agents without a shell use `projects.create_local` and `projects.open_local`.
- **The MCP opens your project itself** when a tool needs the engine.
- **`summer preview`** shows the running game in your agent's own browser, such as Claude Code Desktop's Browser pane.
- **Go live with no wait.** `summer_go_live` releases your build and publishes the store page as soon as Summer's automated checks pass. The new `launch-ready` skill gets a game ready to launch: build, real screenshots, store art and text, then one yes.

- **New skills**: `painted-25d-world` for painted 2D and 2.5D worlds, and `make-content` for postable videos of your game.

</Update>

<Update label="MCP and CLI 4.3" description="October 16, 2026" tags={["MCP and CLI"]}>

## summer-engine 4.3: the CLI reports usage like the MCP server

Released on npm as `summer-engine@4.3.0`.

- **CLI usage lines.** When you are signed in, each `summer` command sends one usage line, like an MCP tool call: the command or operation, success or its error code, the duration and the CLI version. It never sends arguments, paths or project content. Nothing is sent when you are signed out, or when `SUMMER_NO_TELEMETRY` or `DO_NOT_TRACK` is set. `summer login` says what is sent.
- **Error codes in usage.** A failed MCP tool call reports only its error code, such as `not_signed_in` or `engine_not_running`, never the message.
- **Multiplayer publishing.** The `multiplayer-publish` skill no longer tells agents to stop before uploading: Builds pages take the `.zip` bundle.

</Update>

## summer-engine 4.2: Summer without MCP, and skills that stay current

Released on npm as `summer-engine@4.2.0`. Version 4.1.0 was not published; its changes ship in 4.2.0 and are listed here.

**Use Summer from any agent's shell**

- **`summer setup <agent> --cli`** installs the skills and no MCP server. Your agent runs Summer as `summer <area> <action>` commands. See [summer setup](/mcp/cli-reference#summer-setup).
- **New `summer-cli` skill.** It teaches your agent to sign in, find and run operations, wait for long jobs, handle approvals and save files from the shell. See [summer-cli](/skills/summer-cli).
- **Every operation is found without signing in.** `summer ops search` and `summer ops describe` list every cloud operation signed out and mark it "(needs sign-in)".
- **Search understands plain English.** "publish my game" finds `store.publish`, "how did my game do" finds `analytics.summary`, "lower my price" finds `pricing.set_base`.
- **`--json` on every read command**, such as `summer status`, `summer skills list` and `summer ops describe`.
- **Each skill shows the shell command** for every tool and operation it names, in a "From a shell" table.
- **Install with Homebrew:** `brew install summerengine/tap/summer`.

**Agents stay current**

- **Skills refresh after an upgrade.** The first `summer mcp` start after an upgrade brings the installed Summer skills to the new version. Skills you changed yourself stay as they are.
- **Every Summer project gets an `AGENTS.md`** with how to work on the game, plus a `CLAUDE.md` that imports it. `summer setup --yes` adds them to an existing project when they are missing, and never overwrites your own.
- **Ask less on the CLI path.** `summer setup claude-code --cli --allow-rules --yes` lets Claude Code run read-only and dry-run `summer` commands without asking. Codex gets the same rules. Changes, publishing, prices, deletes and messages still ask. `--remove-allow-rules` takes the rules out.
- **`summer_call` takes `name` as well as `op`.**

**Agents and directories**

- **Devin Desktop (formerly Windsurf):** setup writes the MCP config to `~/.config/devin/mcp_config.json`. See [Devin Desktop](/mcp/devin-desktop).
- **Gemini CLI extensions include the skills.** See [Gemini CLI](/mcp/gemini).
- **A Claude plugin** for Anthropic's plugin directory, and new names, icons and descriptions in the MCP Registry and the Codex, Cursor and Claude plugin listings.
- **Content operations are an area:** `summer content <action>`. The 4.0 `marketing.*` content operations are renamed, and the old names keep working.

</Update>

## Summer 4.0: one URL, one sign-in, every capability an operation

Summer is the game engine built for AI. Any agent builds, tests and publishes a full multiplayer game.

- **One hosted URL and one sign-in.** Add `https://mcp.summerengine.com/mcp` to your agent and sign in once. Nothing to install for cloud work. Engine work uses the local server: `npx -y summer-engine@latest setup <agent> --yes`. See [MCP setup](/mcp/setup).
- **Every capability is an operation.** One name such as `store.publish`, one input, one answer. Common jobs have their own tools; `summer_search` finds any operation from the job in plain words, and `summer_call` runs it. See [Operations](/mcp/operations) and [How Summer answers](/api-reference/mcp).
- **Agent permissions and approval links.** Six switches in Studio Settings say what your agents may do without asking. These defaults apply now; you can change them soon. Until then, Summer Games still asks the game's owner before an agent publishes, and price, A/B test and member changes ask you first. When a change asks, your agent gives you a link, `https://www.summerengine.com/studio/approvals/<id>`, and a card shows in Studio. See [Agent permissions](/mcp/permissions).
- **Agent activity with Undo.** Studio Settings lists what your agents changed, with Undo for prices, sales, member roles, team names and the event limit.
- **Auto top-up.** When your credits fall below an amount you pick, Summer adds an amount you set, up to a monthly limit. Agents spend within it. Add credits at `https://www.summerengine.com/studio/credits`. See [Credits and auto top-up](/essentials/account-billing#credits-and-auto-top-up).
- **Operations from the shell.** `summer <area> <action>`, with `--dry-run`, `--wait` and `--json`. See [Operations from the shell](/mcp/cli-reference#operations-from-the-shell).
- **3.x names keep working.** Every 3.x tool name still runs through `summer_call` for all of 4.x. See [3.x tool names](/mcp/operations/legacy-names).

</Update>

<Update label="MCP and CLI 0.5.47" description="July 11, 2026" tags={["MCP and CLI"]}>

## Build games by drawing on them

Design Mode is a new way to work inside your scene. Click a node in 2D or 3D and a chat bar floats on the viewport. Describe what you want changed and the message goes into the same chat you already have in the sidebar. Same model, same history, same project context.

You can also draw on the viewport. Circle an area, sketch where something should go, mark a problem spot. Summer captures a screenshot of your annotation and sends it with your message. The AI sees your point of view, not a generic scene dump.

Fullscreen Iteration Mode fills the window with your scene and keeps a bar at the bottom. Collapse the chat sidebar or press Cmd+Shift+M (Ctrl+Shift+M on Windows). You stay in the game view while the conversation continues underneath.

## Skills teach Summer how you build

Skills are short playbooks Summer reads when the moment calls for it. Lighting a 3D scene, scaffolding a survivors game, debugging physics, shipping performance fixes. Summer ships a library covering the full game dev workflow.

Type `/` in the chat to trigger a skill. `/make-game`, `/debug`, `/optimize`, and `/assets` are built in. Open Settings → Skills to read any playbook, customize it for your style, or write a new one. Skills scoped to a project override your global skills, which override Summer defaults.

When you say "remember how we did this," Summer can draft a skill and show it in a card. Nothing saves until you approve. Facts about your game go to Memory. Repeatable workflows become skills.

## A rebuilt agent team

The main agent is the orchestrator. It plans, talks to you, and hands work to specialists that run in parallel.

**Explore** reads your project and answers focused questions. **Builder** is the hands-on expert for scenes and gameplay. It writes scripts, edits scenes, sets the main scene, binds input, and runs compile checks. **Studio Asset Agent** generates images, 3D, audio, and animation. **Summer expert** verifies engine work and repairs what is broken. **General Advisor** is the slower second opinion when the plan is unclear.

Each specialist streams live in a side panel. You can follow the transcript, continue a thread, steer mid-run, or stop a run. Results fold back into the main chat as summaries. Long asset jobs still run on background workers and wake the chat when they finish.

## Permission modes

You choose how much runs without asking. **Manual** approves every edit, command, and generation. **Accept edits** auto-runs file changes but asks before spending credits. **Auto approve** (default) runs edits and generation but still blocks destructive actions. **Bypass** runs everything except hard safety blocks like protected files and catastrophic shell commands.

## Everything else in 0.5.47

**Context breakdown.** See how much of the context window goes to system prompt, tools, rules, skills, subagents, and conversation.

**Dictation.** Hold the mic in the composer, speak your prompt, release to insert.

**Work visibility.** The chat shows what Summer is doing right now, including when it is waiting on a subagent.

**Reliability.** Expert runs persist across reloads. Chat history finds projects by fingerprint. The update banner tracks slow applies correctly. Design Mode overlay stays transparent on Windows WebView2.

**Under the hood.** AI SDK 7, a custom in-process expert harness, first-class OpenAI-family adapters, and Auto mode on GPT-5.6 Luna at high reasoning. The old queued delegation path is gone. Railway now handles long asset generation only.
