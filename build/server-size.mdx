Every World runs on its own Summer server. You choose two things: how much
computing power and memory that server gets, and how many players one World
can hold. Start small, play your game hosted with the number of players you
expect, and move up a size only when it needs more.

## Games like this

These are starting points, not promises. How much your game needs depends on
what it does every frame, so measure your own game.

## What you get

<img className="block dark:hidden" src="/images/build/server-size/sizes-light.svg" alt="Eight server sizes from Small with 256 MB of memory up to 8XL with 64 GB, each one larger than the last." />
<img className="hidden dark:block" src="/images/build/server-size/sizes-dark.svg" alt="Eight server sizes from Small with 256 MB of memory up to 8XL with 64 GB, each one larger than the last." />

Each size gives the server a guaranteed share of the computer's processor, and
lets it burst higher when spare power is available. Memory is a fixed
budget.

| Size | Memory | Guaranteed CPU | Can burst to |
|---|---|---|---|
| Small | 256 MB | 0.1 CPU | 1 CPU |
| Medium | 512 MB | 0.25 CPU | 1 CPU |
| Standard | 1 GB | 0.5 CPU | 1 CPU |
| Large | 4 GB | 1 CPU | 2 CPUs |
| XL | 8 GB | 2 CPUs | 4 CPUs |
| 2XL | 16 GB | 4 CPUs | 8 CPUs |
| 4XL | 32 GB | 8 CPUs | 16 CPUs |
| 8XL | 64 GB | 16 CPUs | 32 CPUs |

- **Memory is a hard budget.** A server that uses more memory than its size
  allows is stopped, so leave some headroom.
- **Every size can run one full CPU** for your game's main loop. Only extra
  work in parallel, such as loading on other threads, can hit the limit on the
  smaller sizes.
- **Your choice is saved with each version of your game.** Publishing a new
  version with a new size changes the servers for new Worlds; running Worlds
  keep the size they started with.

## Pick your setup

### One size for the whole game

Set one size for every World your game starts. You choose it in your
project, or in the dashboard when you publish a version of your game.

<Prompt description="**Choose a server size for my game.** My agent picks a starting size and sets it.">
In my Summer project, choose a server size for my game's Worlds. Use the
Summer `multiplayer-project` and `multiplayer-publish` skills, and search the
Summer library and the Summer API docs for server tiers; if you don't have the
skills installed, find them in the Summer library.

Read my project first: look at what the server does every frame, how many
players a World holds, and how much it loads. Suggest a starting size, explain
why, and set it. Tell me how to check it once the game is hosted.
</Prompt>

### Different sizes for different worlds

A game can run more than one kind of World, and each kind can have its own
size. A small 1v1 duel can run on Small while your big shared world runs on
XL. A World type without its own size uses the game's size.

### How many players a World holds

Each kind of World can set the most players it admits, from 1 up to 1,024.
This is separate from the server size: one sets how many people can be in the
World, the other how much power the server has to run it. A matchmaking
queue for that World uses the same maximum, and its minimum is how many
players it needs to start. See [Matchmaking](/build/matchmaking).

## Testing it on your machine

Local Play runs your server on your own computer, so it doesn't tell you which
size you need. To pick one, publish your game and play it with as many players
as you expect. Keep an eye on how smooth it feels and on the server's output in
your creator dashboard, then move up or down a size in your next version.
