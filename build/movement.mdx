In a Summer game, each player's own device moves their character. Pressing a
key moves the character that same frame, and the camera follows at once, on
any connection. The server doesn't run anyone's movement. It checks each
position a player sends and sends the ones it accepts to everyone else, who
see that player glide smoothly.

## What your players get

<img className="block dark:hidden" src="/images/guide-art/movement/loop-light.svg" alt="The owner's device moves the character at once and sends its position about 20 times a second. The server checks each position and sends accepted ones to the other players, who glide between them." />
<img className="hidden dark:block" src="/images/guide-art/movement/loop-dark.svg" alt="The owner's device moves the character at once and sends its position about 20 times a second. The server checks each position and sends accepted ones to the other players, who glide between them." />

- **No input delay.** Their own character responds the moment they press a
  key, whatever their ping.
- **Smooth other players.** Everyone else is drawn a fraction of a second in
  the past, gliding between positions, so they move smoothly even when
  packets arrive late or get lost.
- **No speed hacks.** The server checks every position. A move that's too
  fast or out of bounds is refused, and that player snaps back to where they
  last were allowed to be.

## Pick your setup

### Walk, run and jump

Your existing character controller keeps working: input, walking, gravity,
jumping and collision all run on the player's own device. About 20 times a
second it sends the character's position and facing to the server. Your
server decides what's allowed, such as a top speed and the edges of the
level, and gives a little leeway for jumps and falls so normal play never
snaps back.

### The server moves a player on purpose

Sometimes the server needs to put a player somewhere: a respawn point, a
portal, the start of a new round. The server sets the new position, and that
player's character jumps straight there. Everyone else sees them appear at
the new spot rather than slide across the map.

## Testing it on your machine

Local Play runs your server and several game windows on one computer, so you
can walk every character around at once. Your own machine has no lag, so
also run it with added delay, jitter and packet loss. A good run looks like
this: your own character never stutters or snaps back while moving normally,
and the others glide smoothly in every window. See
[Make your game multiplayer](/build/multiplayer#testing-it-on-your-machine).
