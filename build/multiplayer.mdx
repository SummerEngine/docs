A Summer multiplayer game is **one project with two starting scenes**. The
**client** scene is what every player runs: input, camera, visuals and menus.
The **server** scene runs without a screen and owns the rules: the score, the
doors, who won. Summer runs the server for every match, so no player has to
host, and nobody needs to share an address.

The same code runs on your machine and once the game is published. There's no
separate "server version" to keep in sync, and no local-only shortcuts to
remove later.

A few words come up on every page in this section:

- **World:** one running match or shared place, run by one server. A
  10-minute round is a World, and so is a server that stays up for weeks.
- **Session:** one player's seat in a World. Summer checks who the player is
  before they get one, so your server always knows exactly who did what.
- **Queue:** how players find a World, such as "casual" or "ranked 2v2". See
  [Match players into games](/build/matchmaking).

## What your players get

- **Instant controls.** Each player's own character responds the moment they
  press a key, on any connection. See [Make movement feel instant](/build/movement).
- **A fair game.** The server checks every move and request, so a modified
  client can't give itself points, speed or items.
- **Nobody ends the match by leaving.** No player is the host. If someone
  quits or drops out, everyone else keeps playing, and a player who reconnects
  in time gets their seat back.
- **The same account everywhere.** Players sign in once with their Summer
  account, and your game sees their name in every match.

## The project

One project holds both sides. Each folder belongs to one side:

```text
project.godot            shared
summer.build.json        the Build: game id, queues, Worlds, server export preset
world.json               the World: which scene runs on the server, which on players' devices
network/                 shared by both sides: the network composition and shared code
client/                  what players run: main scene, player scenes, UI
authority/               what the server runs: main scene and the rules
```

Client code never loads a file from `authority/`, and the export for players
leaves that folder out.

## The code

This is the client's main script from the `multiplayer-project` skill. It
starts Summer, joins the match queue, and tells the server it has arrived. Each
player runs it. The other files, scenes included, are in
[the complete files](/skills/multiplayer-project/files), and every one of them
ran as shown under Local Play.

```gdscript client/main.gd
extends Node
## What each player runs: joins the match and shows every player.

const Game = preload("res://network/game.gd")
const PlayerArchetype = preload("res://client/player_archetype.tres")

var spawner: SummerNetworkSpawner

func _ready() -> void:
	spawner = Game.build_network(self, PlayerArchetype)
	# Connect signals like state_group_created here, before joining, or values
	# that arrive during the join go unseen (multiplayer-movement adds them).
	var initialized: SummerResult = await Summer.initialize().get_result_or_completed_signal()
	if not initialized.ok:
		push_error(initialized.message)
		return
	var join := Summer.client.join(SummerJoinTarget.queue(Game.QUEUE))
	# Hosted matchmaking may ask the player to accept a match.
	join.acceptance_required.connect(func(proposal: SummerMatchmakingProposal) -> void: proposal.accept())
	var joined: SummerResult = await join.get_result_or_completed_signal()
	if not joined.ok:
		push_error("join failed: %s %s" % [joined.code, joined.message])
		return
	if not spawner.is_network_ready():
		await spawner.network_ready
	var entered := await command({"c": "join"})
	if not entered.ok:
		push_error("could not enter the match: %s" % entered.error)
		return
	print("COURTYARD_CLIENT_JOINED")

## Sends one Command and waits for the authority's answer.
func command(payload: Dictionary) -> Dictionary:
	var admission := spawner.enqueue_command(Game.CMD, Game.pack(payload))
	if not admission.is_enqueued():
		return {"ok": false, "error": String(admission.get_code())}
	var handle := admission.get_handle()
	if not handle.is_terminal():
		await handle.completed
	if handle.get_outcome() == SummerNetworkCommandHandle.OUTCOME_ACCEPTED:
		return {"ok": true, "error": "", "result": Game.unpack(handle.get_result())}
	return {"ok": false, "error": String(handle.get_reason())}
```

Three rules hold for every Summer multiplayer game:

- **`Summer.initialize()` takes no game ID.** Summer knows the game from where
  it runs: Local Play, the hosted server or the Summer Games app.
- **The server decides.** Players send requests, called Commands, and the
  server accepts or refuses each one. It reads who sent a Command from the
  verified session, never from the payload.
- **Use Summer's multiplayer nodes**, `SummerNetworkWorld` and
  `SummerNetworkSpawner`, not hand-written networking. That is what lets Summer
  host the match, check every player and keep the game fair.

Every method and signal: [`Summer.client`](/api-reference/gdscript/client),
[`Summer.multiplayer`](/api-reference/gdscript/multiplayer) and the
[Summer API overview](/api-reference/gdscript/overview).

## Testing it on your machine

**Local Play** runs your whole multiplayer game on one computer. Summer starts
the server scene in the background plus one game window per player, side by
side, each signed in as a test player. No account, server or extra tools are
needed.

<img className="block dark:hidden" src="/images/guide-art/multiplayer/local-play-light.svg" alt="Pressing Play in Summer starts the server scene in the background and three game windows side by side, each signed in as a different test player." />
<img className="hidden dark:block" src="/images/guide-art/multiplayer/local-play-dark.svg" alt="Pressing Play in Summer starts the server scene in the background and three game windows side by side, each signed in as a different test player." />

Start it any of these ways:

- **Your agent**: ask for "a Local Play test with two players".
- **The editor**: choose the number of players in **Debug > Local Multiplayer**, then press Play.
- **A terminal**, while Summer Engine is open:

  ```bash
  npx -y summer-engine@latest engine play --players 2
  ```

The number of players defaults to the queue's `minPlayers` in
`summer.build.json`, or 2.

Your own machine has no lag, which hides timing problems. Local Play can add
delay, jitter and packet loss to every window: set
`summer/local_play/network/round_trip_msec`, `jitter_msec` and `loss_percent`
in Project Settings, or ask your agent. Run it that way before you call a
feature done.
