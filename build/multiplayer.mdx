A Summer multiplayer game is **one project with two starting scenes**. The
**client** scene is what every player runs: input, camera, visuals and menus.
The **server** scene runs without a screen and owns the rules: the score, the
doors, who won. Summer runs the server for every match, so no player has to
host, and nobody needs to share an address.

The same code runs on your machine and once the game is published. There's no
separate "server version" to keep in sync, and no local-only shortcuts to
remove later.

A few words come up on every page in this section:

- **World:** one running match or shared place, run by one server. A
  10-minute round is a World, and so is a server that stays up for weeks.
- **Session:** one player's seat in a World. Summer checks who the player is
  before they get one, so your server always knows exactly who did what.
- **Queue:** how players find a World, such as "casual" or "ranked 2v2". See
  [Match players into games](/build/matchmaking).

## What your players get

- **Instant controls.** Each player's own character responds the moment they
  press a key, on any connection. See [Make movement feel instant](/build/movement).
- **A fair game.** The server checks every move and request, so a modified
  client can't give itself points, speed or items.
- **Nobody ends the match by leaving.** No player is the host. If someone
  quits or drops out, everyone else keeps playing, and a player who reconnects
  in time gets their seat back.
- **The same account everywhere.** Players sign in once with their Summer
  account, and your game sees their name in every match.

## Testing it on your machine

**Local Play** runs your whole multiplayer game on one computer. Press Play
and Summer starts the server scene in the background plus one game window per
player, side by side, each signed in as a test player. Choose the number of
players in **Debug > Local Multiplayer**. No account, server or extra tools
are needed, and your agent can start it for you.

<img className="block dark:hidden" src="/images/guide-art/multiplayer/local-play-light.svg" alt="Pressing Play in Summer starts the server scene in the background and three game windows side by side, each signed in as a different test player." />
<img className="hidden dark:block" src="/images/guide-art/multiplayer/local-play-dark.svg" alt="Pressing Play in Summer starts the server scene in the background and three game windows side by side, each signed in as a different test player." />

Your own machine has no lag, which hides timing problems. Local Play can add
delay, jitter and packet loss to every window, so you see what players on a
real connection will see. Run it that way before you call a feature done.

<Prompt description="**Test my multiplayer game on a bad connection.** Several players, real lag, and what a passing run shows.">
Test my Summer multiplayer game with Local Play. Use the Summer
`multiplayer-testing` skill; if you don't have it installed, find it in the
Summer library.

- Run [N] players, first on a normal connection and then with added delay,
  jitter and packet loss.
- Walk through [THE FEATURE] in every window.
- Tell me exactly what you saw in each window, and anything that looked wrong.
</Prompt>
