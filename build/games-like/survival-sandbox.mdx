A survival or sandbox game is a place, not a match. Players build something
together, log off, and come back days later to find it exactly as they left
it. Summer keeps that World on a server, saves it, lets it sleep while nobody
is online, and wakes it when the next player joins. This page shows how the
pieces fit together.

## How it fits together

<img className="block dark:hidden" src="/images/guide-art/games-like/survival-sandbox-light.svg" alt="The survival loop: a player joins their World, builds with others, the server saves the World, the World sleeps when nobody is online, and it wakes right where it was when the next player joins." />
<img className="hidden dark:block" src="/images/guide-art/games-like/survival-sandbox-dark.svg" alt="The survival loop: a player joins their World, builds with others, the server saves the World, the World sleeps when nobody is online, and it wakes right where it was when the next player joins." />

A player opens one of their Worlds and joins it. While people play, your
server saves the World at regular checkpoints and before it stops. When the
last player leaves, the World goes to sleep. The next player to join wakes it,
and the server restores the last save before anyone walks in.

## Plan my game

<Prompt description="**Plan my survival game.** Your agent reads your project and lays out the Summer pieces in the order to build them.">
I'm making a shared survival or sandbox game like a Minecraft server in
Summer. Read my project and plan how to build it with these Summer skills, in
this order; if you don't have them installed, find them in the Summer
library:

1. `multiplayer` and `multiplayer-project`: the server and client scenes and
   a first Local Play run.
2. `multiplayer-movement`: each player moves their own character instantly.
3. `multiplayer-state`: placed blocks, chests and doors, owned by the server.
4. `summer-world-saves`: the World saves, sleeps and restores.
5. `summer-player-data`: each player's inventory follows them.
6. `summer-world-chat` and `summer-friends`: talk in the World and see
   friends.

For each step, tell me what changes in my project and what I'll see when I
test it. Don't change any files yet.
</Prompt>

## Build the signature features

### A World that remembers everything

<Prompt description="**Make my World persistent.** Builds survive restarts, and the World restores before anyone joins.">
In my Summer project, make my World persistent: everything players build is
saved on the server and is still there after the World sleeps and wakes. Use
the Summer `summer-world-saves` skill; if you don't have it installed, find it
in the Summer library.

- Save at regular checkpoints, and once more before the World stops.
- Restore the last save before the first player is let in.
- Keep the save format the same across game updates, so existing Worlds keep
  loading.

Read my project first and tell me what my World needs to save. Then test it
with Local Play and tell me what you saw, and what only a hosted World proves.
</Prompt>

### Inventories that follow the player

<Prompt description="**Save each player's inventory.** It follows them to every World.">
In my Summer project, save each player's inventory and stats so they follow
the player between sessions. Use the Summer `summer-player-data` skill; if you
don't have it installed, find it in the Summer library.

Load the player's save when they join, save when it changes and when they
leave, and make sure a crash never loses more than a few seconds. Read my
project first, then test it with Local Play and tell me what you saw.
</Prompt>
