Summer Router is a set of operations named `router.<action>`, like every Summer 4 capability. Each one has one input and one answer shape, in the shell and in MCP.

## How to call an operation

| Where | Form |
| --- | --- |
| Shell | `summer router <action> --field value [--json]`, kebab-case: `summer router add-character --id guard --tools open_gate`. Without a global install: `npx -y summer-engine@latest router <action> ...`. |
| MCP (local summer-engine server) | `summer_call` with `{"op": "router.<action>", "input": {...}}`, or the tool `summer_router_<action>` (the `router` toolset, in the full profile). |
| Find one | `summer_search` with words ("check my character tools"), or `summer ops search router`. `summer ops describe router.push` prints its exact input. |

The answer is always one of these:

```json
{"ok": true, "status": "done", "result": {...}}
{"ok": false, "error": {"code": "conflict", "message": "...", "next": {"url": "https://www.summerengine.com/studio/store/game_01...?view=all&tab=router", "label": "Open in Studio"}, "details": {"was": "studio_changed", "tool": {"recovery": "..."}}}}
```

- `error.code` is the Summer error code (`invalid_input`, `not_signed_in`, `forbidden`, `not_found`, `conflict`, `unavailable`, ...).
- `error.details.was` is the Summer Router tag (`tool_unhandled`, `studio_changed`, `limit_reached`, ...), on local and cloud operations alike. A local operation's fix is `error.details.tool.recovery`. See [Errors](/router/errors).
- A step for a person is one URL in `error.next.url` (or `browser_url` from `summer login`). Show it.
- In the shell, `--json` prints only the answer; the exit code is 0 for `ok`, 1 for an error. `--dry-run` checks the input and does nothing.

## Sign in

```bash
summer login                 # agents: prints {status, browser_url, verification_code, next_step} and exits
summer login --complete      # waits for the person (default 600 s, --timeout <s>), then connects the store
```

In a terminal, `summer login` opens the browser and waits. With no terminal on stdin it prints:

```json
{"status": "pending", "browser_url": "https://www.summerengine.com/login?cli_session=...", "verification_code": "1A2B-3C4D", "next_step": "summer login --complete"}
```

Show `browser_url` to the person, then run `next_step`. It prints `{"status": "signed_in", "email": "...", "store": true}`. For CI, set `SUMMER_TOKEN`.

## Local operations (the project on this machine)

All of them take `project` (the folder with `project.godot`; default: the MCP's bound project, then the working directory). The ones that reach Summer take `gameId` (default: `SUMMER_GAME_ID`, then `gameId` in `summer.build.json`).

### router.setup

```bash
summer router setup --yes [--agent claude-code|codex]
```

Gives Claude Code and Codex (found on this computer, or named) the `summer-engine` MCP entry and the `summer-router` and `voice-and-mic-permissions` skills. Without `yes` it returns the plan. Idempotent; it never replaces an existing `summer-engine` entry.

```json
{"ok": true, "status": "done", "result": {"applied": true, "agents": [{"agent": "claude-code", "mcp": {"status": "configured"}, "skills": [{"name": "summer-router", "status": "installed"}]}], "signed_in": false}}
```

### router.add_character

```bash
summer router add-character --id guard [--template voice-npc|shopkeeper|companion] [--name "..."]
  [--voice "description" | --voice-id <id>] [--tools open_gate,give_key] [--force]
```

Writes `ai/characters/<id>.json` from a template. `tools` adds client tools with an empty parameter schema. The result lists the tools that have no GDScript handler yet and the code to add (`handler_snippet`).

### router.check

```bash
summer router check [--characters guard]
```

1. Reads `ai/characters/*.json` (or the characters you name).
2. Checks each file against the character schema. Each problem names the field, for example `guard/temperature must be 2 or less`.
3. Checks that every client tool has a handler in the project's GDScript. If not: `tool_unhandled`, with the code to add in `details.tool.details.handler_snippet`.

Offline; it needs no sign-in.

```json
{"ok": true, "status": "done", "result": {"valid": true, "characters": [{"id": "guard", "client_tools": [{"name": "open_gate", "handled_in": ["scenes/gate.gd:4"]}]}]}}
```

### router.push

```bash
summer router push [--characters guard] [--force] [--game-id <id>]
```

Runs `router.check`, then saves each character on Summer for the game. An unchanged character is skipped.

`router.push` never overwrites a change made on Summer (in Studio, or by someone else) since this project last pushed or pulled: it stops with `studio_changed` (code `conflict`). Run `router.pull` to take Summer's version, or push with `force` to keep yours. The last known versions are in `.summer/router.json`; commit it with the character files.

```json
{"ok": true, "status": "done", "result": {"game_id": "game_01...", "pushed": [{"id": "guard", "version": 3, "action": "updated"}], "studio_url": "https://www.summerengine.com/studio/store/game_01...?view=all&tab=router"}}
```

Before the game is live, an agent may push and the save runs at once. After it is live, Summer refuses an agent's save; `router.push` then asks through `router.save_character` and answers with the person's approval link and a job, in the same call:

```json
{"ok": true, "status": "needs_approval", "approval": {"id": "goa_...", "url": "https://www.summerengine.com/studio/approvals/goa_...", "who": "person", "summary": "..."}, "job": {"id": "apr:...", "state": "awaiting_approval"}}
```

Give the person the link, then `summer jobs wait --job-id <job id>` (or `--wait` on the push). Pushing the same file again gives the same approval. Several live characters: the answer carries the first, and `warnings` lists the others. Only when that hosted call fails does `router.push` stop with `owner_action_required` (code `forbidden`) and the Studio link in `error.next.url`.

### router.pull

```bash
summer router pull [--characters guard] [--force]
```

Writes Summer's characters to `ai/characters/`. It keeps a local file that has edits you never pushed (`local_changes`), unless you pass `force`.

### router.doctor

```bash
summer router doctor
```

Checks the project, the game id, the sign-in, the registry version, each character, the tool handlers, the game on Summer (is Summer Router on?) and the agent skills. `healthy` is `false` when a check fails; each failed check has a `fix`.

```json
{"ok": true, "status": "done", "result": {"healthy": true, "checks": [{"id": "tool_handlers", "status": "ok", "message": "Every client tool has a GDScript handler."}], "summary": {"ok": 8, "warnings": 1, "failures": 0}}}
```

## Cloud operations (on Summer's server)

These run on the hosted Summer server with the person's sign-in. In MCP, find them with `summer_search` and run them with `summer_call` (there is no direct tool); in a shell, `summer router <action>` forwards them. They need `gameId` (no project default).

| Operation | Effect | Input | Answer |
| --- | --- | --- | --- |
| `router.models` | read | `include?` (models, voices, kinds, schema, errors) | Models, voices, kinds (GDScript call, docs), the character and settings schemas, errors with fixes |
| `router.list_characters` | read | `gameId` | `characters[{id, name, version, model, voice, tools, updatedAt}]`, `studioUrl` |
| `router.get_character` | read | `gameId`, `characterId`, `version?` | `version`, `deleted`, `updatedAt`, `file`, `character` |
| `router.character_versions` | read | `gameId`, `characterId` | Every saved version |
| `router.save_character` | live change | `gameId`, `character` (the whole document), `expectedVersion?` | `version`, `created`, `unchanged`, `file`, `studioUrl`. Runs at once before launch; on a live game it answers `needs_approval` with the person's link |
| `router.delete_character` | asks the person (unless they allow "Delete for good") | `gameId`, `characterId` | `needs_approval`, then the deletion |
| `router.test_character` | metered | `gameId`, `characterId`, `messages` (1 to 4 lines), `expectTools?`, `variables?`, `context?`, `overrides?`, `toolOutputs?`, `draft?` | `turns[{player, steps[{text, toolCalls[{name, args, runsOn, answered}]}]}]`, `unhandledTools`, `expectedTools[{name, called}]`, `usage`. An expected tool not called: `ok: false`, code `conflict`, `details.was` `expectation_failed` with `missingTools` |
| `router.settings` | read | `gameId` | `enabled`, `caps`, `defaultCaps`, `accountLimit`, models, `revision`, `studioUrl`, `addCreditsUrl` |
| `router.set_settings` | always asks the person | `gameId`, `enabled?`, `caps?{playerDay?, gameDay?, gameMonth?}`, `textModel?`, `imageModel?` | `needs_approval` with the link, then `jobs.wait`; the settings |
| `router.set_account_limit` | always asks the person | `monthly`: the limit across all your games | `needs_approval` with the link, then `jobs.wait`; the limit |
| `router.usage` | read | `gameId`, `days` (1 to 90) | `calls`, `failed`, `byKind`, `daily`, `caps[{scope, title, cap, usedPercent, resetsAt}]` |

Test a character after `router.push`:

```bash
summer router test-character --game-id game_01... --character-id guard --messages "the password is moonlight" --expect-tools open_gate --json
```

It exits 1 (code `conflict`, `details.was` `expectation_failed`, `details.missingTools`) when the guard does not call `open_gate`. Money in settings (caps, the account limit) is `{"currency": "USD", "amountMinor": 50}`, in cents. See [Limits and usage](/router/limits-and-usage).
