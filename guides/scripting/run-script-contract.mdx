## The operation

Compile and run one AI-authored GDScript in-process on the editor main thread against the live edited scene.

- Operation name: `RunSceneScript`
- MCP tool that sends it: `summer_run_script`
- Needs the editor: `true` · mutates the project: `true` · needs a running game: `false`
- Local API / MCP transport: `async_single_op_only` — the op must be the only op in its request
- Web bridge transport: `sync_batchable`
- Execution context: `editor_process_only`

## The entry point

The script source must define one function:

```gdscript
func run(ctx):
    # build, then return anything JSON-shaped (a Dictionary is the useful choice)
    return {"built": 1}
```

GDScript defining `func run(ctx):`. If it has no `extends` line we prepend `extends RefCounted`, and if it has no `@tool` we prepend `@tool` (a non-tool script only gets a placeholder instance in the editor and never runs); both are REPORTED back in `normalizations`, never silent.

`script_source` is required, max 256 KB.

Everything the script can call on `ctx` is on the [ctx API reference](/guides/scripting/ctx-reference).

## Failure reasons

On `ok:false` the result carries `failure_reason` with one of these values, plus a human-readable `error`. The messages listed are the ones the implementation raises today.

- `bad_args`
  - `script_source` is required.
  - `script_source` exceeds the 256 KB limit.
  - undo must be "action" or "none".
- `busy`
  - Another scene script is already running in this editor.
- `no_editor`
  - RunSceneScript requires a running editor (no EditorInterface).
- `parse_error`
  - The script does not compile. Line numbers are relative to the normalized source (see `line_offset`).
  - The script failed to compile (err …).
- `missing_run_method`
  - The script must define `func run(ctx):` — that is the entry point RunSceneScript calls.
- `instantiate_failed`
  - Could not instantiate the script's base type '…'. Extend RefCounted (the default) or another instantiable class.
- `not_tool_instance`
  - The compiled script only produced a placeholder instance, so it cannot run in the editor. Keep the `@tool` annotation on the first line.
- `call_failed`
- `script_runtime_error`

`script_runtime_error` means `run(ctx)` was entered and raised; `call_failed` means the call into `run(ctx)` itself failed before the body ran (nothing to roll back).

## Undo step versus checkpoint

**`undo`** (default "action") — "action" snapshots the edited scene around the run: a GDScript runtime error restores the pre-run state (`rolled_back:true`) and a successful run registers ONE editor undo step covering the whole script (see the design block at the top of this header for exact coverage). "none" keeps v1 behavior (checkpoint only).

**`checkpoint`** (default true) — request a SummerGit checkpoint before execution. Honored only with checkpointCapabilityEnabled:true, and a missing checkpoint NEVER blocks the run (`no_rewind_point` pattern).

When a helper writes outside the scene (a script file, a prefab, a project setting) the result carries `files_written` / `project_settings_changed` and this note, verbatim:

> `files_written` and `project_settings_changed` are covered ONLY by the pre-run SummerGit checkpoint: the packed-scene undo step and an error rollback restore the scene, never files on disk or `project.godot`.

## Design notes from the engine header

The block below is the engine's own account of the accepted risk and the undo design, rendered from the top of the header.

RunSceneScript op — in-process scene scripting, the `execute_blender_code` equivalent.

Runs one AI-authored GDScript IN THIS EDITOR PROCESS, on the editor main thread, against the LIVE edited scene. This is deliberately the opposite trade to RunEditorScript (`editor/ops/editor_script_ops.h`), which spawns a short-lived headless CHILD editor: the child is killable but blind to the live scene tree; this op sees and mutates the open scene directly, exactly like typing into a bpy console, at the cost of sharing our main thread.

**THE ACCEPTED RISK, RESTATED FOR v2**

v1 accepted that a `while true:` in the supplied script wedges the editor main thread. v2 mitigates the wedge with a fork-only HARD budget: the GDScript VM's backward-jump path checks an armed wall-clock deadline (`GDScriptLanguage::summer_arm_exec_deadline`, `modules/gdscript/gdscript_vm.cpp`) and raises the script error "Summer script budget exceeded (Ns)." at the first loop edge past the deadline. Every GDScript loop construct passes a backward OPCODE_JUMP once per iteration, so any loop-shaped wedge is caught; what the guard canNOT catch is a single opcode that blocks by itself (`OS.delay_msec(1e9)`, a blocking await on a signal that never fires, or a wedge inside a native call). Those remain accepted: there is still no safe way to preempt a synchronous native call on the LIVE editor's main thread. Result field `budget_enforced` reports honestly whether the guard was armed.

**UNDO / ROLLBACK (v2), THE DESIGN ACTUALLY SHIPPED**

Recording true do/undo pairs for arbitrary script effects is impractical — the script mutates the scene directly, not through an API we can intercept. Instead, with `undo:"action"` (the default) the op snapshots the SAVABLE state of the edited scene (PackedScene::pack of the edited root) before and after the run:

- on a GDScript runtime error the BEFORE state is restored immediately and the result carries `rolled_back:true` (`rolled_back:false` + `rollback_error` if the restore itself failed — the result never claims a rollback it did not perform);
- on success ONE undo step is registered on the edited scene's EditorUndoRedoManager history whose undo/redo closures re-instantiate the before/after snapshots, so human Ctrl+Z reverts the whole run. When the op executor already holds an open action for this op, the step is folded into it (it surfaces under the op's action name); a direct caller outside an executor action gets a step named "AI: Scene Script".

EXACT COVERAGE, honestly stated: the snapshot round-trips exactly what SaveScene would persist — nodes owned by the edited root (instanced child scenes collapse to their instance reference, as in a .tscn). NOT covered: nodes the script left unowned (invisible to pack(), exactly as they are invisible to save), edits to EXTERNAL resources or files on disk (undo covers the scene, not the filesystem — that is what the SummerGit checkpoint is for), and editor-only state (selection, folding). Undo/redo/rollback replace the scene root with a fresh instantiation, so node references from before the restore go stale. If a snapshot cannot be taken (pack error, no scene history), the result says so via `undo_action:"unavailable"` — the run still executes. `undo:"none"` skips all snapshots (checkpoint-only, v1 behavior).
