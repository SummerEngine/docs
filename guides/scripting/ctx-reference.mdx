## What `ctx` is

Your script is one GDScript function, `func run(ctx):`. The engine hands it `ctx`, an instance of `SummerSceneScriptContext`, and every method below is called on it — `ctx.add_mesh(...)`, `ctx.report(...)`. How the script is run, what comes back, and how undo works is on the [run(ctx) contract](/guides/scripting/run-script-contract) page; the ideas behind ownership, budgets and report entries are explained in [Concepts](/guides/scripting/concepts).

The `ctx` argument handed to the script's `func run(ctx):`. Registered in `register_types.cpp` (SCENE level, TOOLS_ENABLED block). v2 carries the full frozen ctx stdlib from `doc/SUMMER/SCENE_SCRIPTING_CONTRACTS.md`: every creation helper adds to the edited scene root when no parent is given, sets owner to the edited scene root by default (the #1 silent persistence gotcha, made structurally impossible), and returns the created node. `props` dictionaries apply via set() per key; keys that match no property are collected into the `prop_warnings` report entry, never silently dropped.

Signatures use GDScript spelling: `name: Type = default -> ReturnType`. A default of `null` means the parameter is optional and the helper picks the edited scene root (for `parent`) or the get-or-create default described in its notes.

_No preamble in source._

Everything a script needs to produce a GAME: 2D, UI, and the gameplay-code lane. Same conventions (owner-by-default, return the node, `prop_warnings`, structured report entries on failure — never silent). 2D helpers work in any edited scene (root may be Node2D or Node); Control helpers parent under the edited root unless a parent is given.

Gameplay-code lane. All three write OUTSIDE the scene (files, project settings): covered by the pre-run checkpoint only, never by the packed-scene undo step — surfaced through the result's `files_written` / `project_settings_changed` + `undo_action_note`.

### attach_script

```gdscript

```

GDScriptLanguage::validate FIRST (parse errors -&gt; `attach_script_errors` report entry with line/column/message, null, nothing written).

Returns the Script.

### make_prefab

```gdscript
make_prefab(node: Node, path: String, replace_with_instance: bool = true) -> Node
```

Packs the node's subtree to a PackedScene at path (owner fix-up first: descendants owned by the edited root are re-owned to the node for the pack and ALWAYS put back; the node's own position is zeroed for the pack and restored, like the editor's Save Branch), saves, registers the file.

`replace_with_instance`: the node is swapped for an instance of the new file (same name, index, parent, transform; outgoing persisted connections re-established; owned by the edited root), the old node is freed and the instance returned. From the contract document's implementation notes:

- `make_prefab`: the node's own position is zeroed for the pack (prefab authored at its origin, the editor's Save Branch default) and restored / copied onto the instance; rotation and scale stay in the prefab.
- A failure AFTER the file was written keeps and returns the original node with `error` in the `make_prefab` report entry.
