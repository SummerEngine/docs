The Summer Engine agent writes better code when it can check the docs instead
of guessing. It reads two kinds: public documentation, and the docs inside your
project.

## What the agent can read

| Source | What it gives the agent |
|---|---|
| Engine API documentation | Classes, methods, properties and syntax. Summer Engine is based on Godot 4, so the agent can read the matching Godot API docs. Check versions against the [compatibility reference](/reference/compatibility). |
| Web search and web pages | Current tutorials, guides and answers. Paste a link and the agent can read the page. |
| Your project | Scripts, scenes, `AGENTS.md`, rule files, READMEs and doc comments. |

Agents connected through the Summer MCP can also search these docs with
`summer_docs_search` and read a page with `summer_docs_read`.

## Point the agent at the right docs

Name the class or page you mean:

```
Read the CharacterBody2D docs, then write a player controller that uses
move_and_slide() and handles slopes.
```

```
Read https://example.com/my-library/README and add it to the project the way
it describes.
```

When an answer looks out of date, say so: "Check the current API docs before
you change this."

## Keep docs in your project

The agent reads files in your project, so docs you keep there help every chat.

**`AGENTS.md` at the project root.** Your structure and conventions, read at the
start of every chat. See [Rules for consistency](/guides/large-codebases#rules-for-consistency).

```markdown title="AGENTS.md"
# Project structure
- systems/combat/: combat logic
- systems/inventory/: items and storage
- ui/: menus and HUD

# Conventions
- Game events go through core/event_bus.gd.
- UI scenes never change game state directly; they emit signals.
```

**Doc comments.** `##` comments above a class, variable or function show up in
the editor's help, and the agent reads them with the code.

```gdscript
## Moves the player and handles jumping.
## Reads input from InputManager and emits events on EventBus.
class_name PlayerController extends CharacterBody2D

## Movement speed in pixels per second. Typical values: 200 to 400.
@export var speed: float = 300.0

## Jump velocity. Negative, because +Y points down.
@export var jump_velocity: float = -400.0
```

**System notes.** A short Markdown file per big system, such as
`docs/combat.md`, with how data flows and which files own what.

## Let the agent write and update docs

```
Read @systems/inventory/ and write docs/inventory.md: what the system does,
its public methods, and how other systems use it.
```

```
I changed the save format in @systems/save_manager.gd.
Update docs/save-system.md to match.
```

```
Before we build quests, write docs/quests.md with the data structure, the
states, and how quests save. Do not write code yet.
```

## A simple team standard

```markdown
- Public methods have ## doc comments.
- TODO comments include an owner and a date.
- Each major system folder has a short README.
- Update the docs in the same change as the code.
```
