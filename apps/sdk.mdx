Load the SDK and the UI kit as ES modules, with root paths, from the app's own host (`apps.summerengine.app`):

```html
<script type="module" src="/summer-sdk/v1.js"></script>
<script type="module" src="/summer-ui/v1/ui.js"></script>
```

A classic `<script>` tag or another path does not work. An app only runs inside Summer Studio: publish it and open it at `/studio/apps/<appId>`. Opening `index.html` on its own never connects, because the app runs in a sandboxed frame (no cookies, no storage, no network) and waits for Studio.

Every method returns a promise and runs as **the person using the app**: their team, their assets, their credits. A call the [manifest](/apps/manifest) does not allow rejects with `permission_missing`. Errors are `SummerError` with a `code` and a `message`.

```js
await summer.ready; // the Studio host connected
```

## app (no permission)

| Call | Does |
|---|---|
| `summer.app.info({ params })` | The app, its version and manifest, and the launch params from the app page URL. |
| `summer.app.viewer()` | Who is using the app: name, role, today's spend through the app, their daily cap. |
| `summer.app.setTitle(title)` | The title in the app page's top bar. |
| `summer.app.notify(text)` | A notice in Studio. |
| `summer.app.needsYou(count)` | The "needs you" badge on the Apps row (0 clears it). |
| `summer.app.open(path)` | Moves Studio to a Studio page (`/studio/...` only). |
| `summer.app.theme()`, `summer.app.onTheme(fn)` | Studio's light or dark theme. |
| `summer.app.onSnapshot(() => state)` | State to keep when Studio moves an idle app to a fresh frame (every few minutes). The new frame reads it from `(await summer.ready).restored`. Up to 256 KB. Shared data needs nothing. |
| `summer.app.busy(on)` | Wrap Web Audio playback in `busy(true)` / `busy(false)` so the frame is not moved mid-sound. `<audio>` and `<video>` count on their own. |

## data (`data`)

```js
const items = summer.data.collection("items");
await items.put("bow", { name: "Bow", damage: 40, speed: 1.2 });
await items.patch("bow", { damage: 36 }, { ifRevision: 4 });
const { records, next } = await items.list({ limit: 200 });
const bow = await items.get("bow");      // { data, revision, actor, updatedAt } or null
await items.remove("bow");
const stop = items.subscribe((change) => render()); // live edits from the team and agents
```

There is no `summer.data.list(name)`: always go through `summer.data.collection(name)`.

| Call | Returns |
|---|---|
| `list({ limit, after })` | `{ revision, records, next, collections }`; pass `next` as `after` for the next page |
| `get(id)` | a record `{ collection, recordId, data, revision, actor, updatedAt, deleted }`, or `null` (also for a removed record) |
| `put`, `patch`, `remove` | `{ revision, operation, records, replayed }` |
| `subscribe(fn)` | a stop function; `fn` gets `{ revision, actor, ops }`, or `{ revision, reset: true }` (then list again) |

`list()` never returns removed records. `actor` is `{ userId, kind: "person" | "agent", agent?, via? }`. Writes an agent made with `summer_app_data`, and writes your code made while running an agent tool for `summer_app_call` (`via: "agent-tool"`), have `kind: "agent"`, so your app can mark agent-made rows. `userId` is the same id as `app.viewer().userId` and `(await summer.ready).viewer.userId`.

Records are JSON up to 64 KB, 10,000 per collection, 50 collections per app. `summer.data.commands({ requestId, baseRevision, ops })` applies up to 100 changes in one revision.

## assets (`assets:read`, `assets:write`)

| Call | Permission |
|---|---|
| `summer.assets.search(q, { filters, limit })` | `assets:read` |
| `summer.assets.get(id)` | `assets:read` |
| `summer.assets.upload({ name, contentType, base64 })` | `assets:write` |
| `summer.assets.saveToLibrary(id, { name })` | `assets:write` |

## generate (`generate`) and ai (`ai`)

These spend the credits of the person using the app, through the same pricing as the rest of Summer. A team can cap spend per app and day (`spend_cap_reached`).

| Call | Makes |
|---|---|
| `summer.generate.image({ prompt })` | An image |
| `summer.generate.sfx({ prompt, durationSeconds })` | A sound effect |
| `summer.generate.sfxChoices({ prompt })` | Several versions of a sound effect to pick from |
| `summer.generate.music({ prompt, durationSeconds })` | Music |
| `summer.generate.voice({ text, voiceId })` | Speech |
| `summer.generate.model3d({ prompt })` or `({ imageAssetId })` | A 3D model (a job) |
| `summer.generate.video({ prompt })` | A video (a job) |
| `summer.generate.job(jobId)` | A job's status |
| `summer.ai.complete({ prompt, system, json })` | Text from a Summer-chosen model |

## agent (no permission)

| Call | Does |
|---|---|
| `summer.agent.send(name, payload)` | An event your agent reads with `summer_app_events`. Declare `name` in `agentEvents`. |
| `summer.agent.onMessage(fn)` | Messages for the app. |
| `summer.agent.tool(name, handler)` | Implements an agent tool declared in `agentTools`. See [Agents and apps](/apps/agents). |

## page (no permission)

`summer.page.declare({ fields, actions })` tells Studio which inputs and buttons your app has, so your agent can read and use them with `summer_app_page`. Give each field a `set(value)` and each action a `run()`. Mark actions that delete, publish, pay or send as `critical`: only the person presses those.

## Errors

| Code | Means |
|---|---|
| `permission_missing` | Add the permission to the manifest and publish again. |
| `invalid` | The arguments are wrong; the message says which. |
| `unknown_method` | Not in SDK v1. Summer records it as a missing capability. |
| `rate_limited` | Too many calls (600 a minute, 60 paid calls a minute per person and app). |
| `spend_cap_reached` | The person's daily cap for this app is reached. |
| `engine_offline` | No Summer Engine is connected for this person. |
| `conflict` | A data change lost a race (`ifRevision`); read again and retry. |
