There are no API keys to copy, store or leak. Your agent signs in to your Summer account in the browser, once, and you choose **Allow** with a spend limit. The sign-in renews itself.

## Sign in

```bash
npx -y summer-engine@latest login
```

The browser opens the Summer sign-in page. Sign in, check which app is asking, pick a monthly spend limit, and choose **Allow**. From then on every `summer api` command uses this sign-in:

```bash
npx -y summer-engine@latest api run image/default --input '{"prompt": "a cozy pixel-art tavern at night"}' --download .
```

## Call the API over HTTP

`summer token` prints a one-hour access token from the same sign-in. Send it as a bearer token:

```bash
export SUMMER_TOKEN=$(npx -y summer-engine@latest token)
curl https://www.summerengine.com/v1/balance -H "Authorization: Bearer $SUMMER_TOKEN"
```

Run `summer token` again for a fresh token; the sign-in behind it stays valid. Reading models (`GET /v1/models`) and pricing a request (`POST /v1/estimate`) need no sign-in.

**Your own app.** Summer's sign-in is standard OAuth 2.1 with PKCE, the same one the Summer MCP uses. Discovery: `https://mcp.summerengine.com/.well-known/oauth-protected-resource`. Send the access token your app gets as `Authorization: Bearer <token>`.

## Spend limits per app

Every app or agent you connect has its own spend limit, chosen on the Allow page: 5, 20 or 50 US dollars a month, your own amount, or no limit of its own. Change it at any time in [Settings > Connected agents & apps](https://summerengine.com/settings/connected-apps), where each app shows its limit, what it spent, when it was last used and when its access ends. **Revoke** stops the app at once; it works again only after you connect it again.

## How spending works

- **Paid credits.** Every call is paid from your paid Summer credits: your plan's credits and your top-ups. [Top up](https://summerengine.com/studio/credits) at any time.
- **A failed job costs nothing.** Most jobs are charged when they succeed. A job that is charged when it starts, such as a video, is refunded in full when it fails.
- **Hard limits.** A call that would go over the app's limit or your paid balance is refused with `402` before any work starts. Several calls at once never go past a limit.
- **Never twice.** Send an `Idempotency-Key` header with each job. A retry with the same value returns the first answer and charges nothing more.

## Read the app's limit and your balance

```bash
curl https://www.summerengine.com/v1/key -H "Authorization: Bearer $SUMMER_TOKEN"
```

Answers `data` for the app behind this token: `name`, `client_id`, `scopes`, `limit_usd`, `limit_reset`, `spent_usd`, `remaining_usd`, `resets_at`, `total_spent_usd`, `expires_at` and `created_at`.

```bash
curl https://www.summerengine.com/v1/balance -H "Authorization: Bearer $SUMMER_TOKEN"
```

Answers `data` with `balance_usd` (your paid credits), `spendable_usd` (what this app can spend now: the balance, or less when its limit is lower), `key_remaining_usd`, `key_resets_at` and `top_up_url`.

All amounts are US dollars. `null` means no limit. Both calls are in the API reference: [Read the app's limit](/api/reference/get-key) and [Read your balance](/api/reference/get-balance).

## Rate limits

Summer limits how fast jobs start for each kind of asset (images, audio, 3D and video). Over the limit, a call answers `429` with a `Retry-After` header in seconds. Wait that long, then send the same request with the same `Idempotency-Key`.

## Keep tokens safe

A token spends your credits for an hour. Keep it in the environment, never in game code, a build or a commit.
