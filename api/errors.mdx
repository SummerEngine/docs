Every error from `/v1` has the same shape:

```json
{
  "error": {
    "type": "billing_error",
    "code": "no_credits",
    "message": "Not enough credits for this. Add credits, no plan needed: https://summerengine.com/studio/credits",
    "param": null,
    "request_id": "req_4f2c...",
    "doc_url": "https://docs.summerengine.com/api/errors#no_credits",
    "fix_url": "https://summerengine.com/studio/credits"
  }
}
```

| Field | Meaning |
|---|---|
| `type` | The group: `invalid_request_error`, `authentication_error`, `permission_error`, `not_found_error`, `billing_error`, `conflict_error`, `rate_limit_error` or `api_error` |
| `code` | A stable code from the list below. Branch on this. |
| `message` | What happened and what to do, in plain words. Show it to the person. |
| `param` | The field to fix, such as `input.prompt` or `Idempotency-Key`, or `null` |
| `request_id` | Also in the `X-Request-Id` header. Send it to Summer support. |
| `fix_url` | Where the person fixes it, such as adding credits. Only when there is one. |
| `doc_url` | This page, at the code's section |

A call that answers an error charges nothing, with one exception: after `outcome_unknown` a job may have started. Send the same request again with the same `Idempotency-Key` to find out. The key request calls of [Agents](/api/agents#get-a-key-from-your-agent) answer with a `status` field instead.

## Codes

| Code | Status | Retry? |
|---|---|---|
| [`invalid_input`](#invalid_input) | 400 | No: fix the request |
| [`moved`](#moved) | 400 | No: use the new name |
| [`not_signed_in`](#not_signed_in) | 401 | No: fix the key |
| [`no_credits`](#no_credits) | 402 | After credits are added |
| [`over_limit`](#over_limit) | 402 | After the limit resets or is raised |
| [`forbidden`](#forbidden) | 403 | No |
| [`not_found`](#not_found) | 404 | No |
| [`conflict`](#conflict) | 409 | After a new estimate |
| [`idempotency_conflict`](#idempotency_conflict) | 409 | With a new key |
| [`in_progress`](#in_progress) | 409 | Yes, the same request |
| [`unsupported`](#unsupported) | 409 | No |
| [`rate_limited`](#rate_limited) | 429 | Yes, after `Retry-After` |
| [`internal`](#internal) | 500 | Yes, once |
| [`outcome_unknown`](#outcome_unknown) | 502 | Check first |
| [`unavailable`](#unavailable) | 503 | Yes, with backoff |

### invalid_input

The request does not match the model's input. `param` names the field, such as `input.duration`, and `message` says what it takes. Read the model's `inputSchema` with `GET /v1/models/{id}`. A missing `Idempotency-Key` header on `POST /v1/jobs` also answers this.

### moved

The name you sent was replaced. `message` names the new one.

### not_signed_in

No key, or the key is wrong, revoked or expired. Send `Authorization: Bearer $SUMMER_API_KEY`. An agent key expires after 30 days: ask for a new one ([how](/api/agents#get-a-key-from-your-agent)).

### no_credits

The account has too few credits for this job. Nothing ran and nothing was charged. `fix_url` opens the page where the person adds credits; no plan is needed. Check what a key can spend with `GET /v1/balance`.

### over_limit

The key reached its own spend limit. Nothing ran and nothing was charged. The person raises the limit in **Settings > API keys**, or the limit resets at `resets_at` from `GET /v1/key`.

### forbidden

This key or account may not do this. An agent key can make assets and spend credits only.

### not_found

No such model, job or route. Model ids come from `GET /v1/models`. Job ids are sent as they are, colon included.

### conflict

The price went up since your `quoteId`. Nothing was charged. Ask `POST /v1/estimate` again and start the job with the new quote.

### idempotency_conflict

This `Idempotency-Key` was already used for a different request. Use a new key for a new job.

### in_progress

A request with this `Idempotency-Key` is still running. Wait a moment and send the same request again: you get its answer.

### unsupported

The job cannot do this, for example cancel an asset job that already started.

### rate_limited

Too many jobs started too fast. Wait the seconds in the `Retry-After` header, then send the same request with the same `Idempotency-Key`.

### internal

Something broke on Summer's side. Retry once with the same `Idempotency-Key`. If it fails again, send `request_id` to Summer support.

### outcome_unknown

Summer could not tell whether the work started. Do not start a new job: send the same request with the same `Idempotency-Key`, which returns the first job if there was one.

### unavailable

A model or a Summer service is down for a moment. Nothing was charged. Retry with backoff, or pick another model for the same job from [the models page](/api/models).
