Every call that makes an asset needs a key. Send it as a bearer token:

```bash
Authorization: Bearer $SUMMER_API_KEY
```

Keys start with `sk-summer-v1-`. Reading models (`GET /v1/models`) and pricing a request (`POST /v1/estimate`) need no key.

## Two kinds of keys

| | Account key | Agent key |
|---|---|---|
| Made by | You, in **Settings > API keys** | `summer login --api-key` or an agent's key request, after you choose **Allow** ([how](/api/agents)) |
| Spend limit | Optional; resets never, every day, week or month | The limit you approved; no reset |
| Expires | Never | After 30 days |
| Can | Make assets and spend credits | Make assets and spend credits |

Summer stores only a hash of each key and shows a key once, when it is made. One account holds up to 50 live keys.

## Create, change and revoke

Open [Summer Studio > Settings > API keys](https://summerengine.com/studio?tab=settings&section=api-keys):

- **Create key**: a name, an optional spend limit and when the limit resets. Copy the key; you will not see it again.
- **Edit limit**: change how much a key may spend. It applies to the next call.
- **Revoke**: the key stops working at once. Anything that uses it gets `401`.

The list shows each key's last four characters, what it spent of its limit, when the limit resets, when it was last used and when it expires.

## How spending works

- **One balance.** Every key spends the credits of the account that owns it. No plan is needed: bought credits are enough.
- **A failed job costs nothing.** Most jobs are charged when they succeed. A job that is charged when it starts, such as a video, is refunded in full when it fails.
- **Hard limits.** A call that would go over the key's limit or the balance is refused with `402` before any work starts. Several calls at once can never overshoot a limit.
- **Never twice.** Send an `Idempotency-Key` header with each job. A retry with the same key returns the first answer and charges nothing more.

## Read a key and your balance

Both are in the API reference: [Read your key](/api/reference/get-key) and [Read your balance](/api/reference/get-balance).

```bash
curl https://www.summerengine.com/v1/key -H "Authorization: Bearer $SUMMER_API_KEY"
```

Answers `data` with `name`, `kind` (`account` or `agent`), `scopes`, `limit_usd`, `limit_reset`, `spent_usd`, `remaining_usd`, `resets_at`, `total_spent_usd`, `expires_at` and `created_at`. Never the key itself.

```bash
curl https://www.summerengine.com/v1/balance -H "Authorization: Bearer $SUMMER_API_KEY"
```

Answers `data` with `balance_usd` (your credits), `spendable_usd` (what this key can spend now: the balance, or less when the key's limit is lower), `key_remaining_usd`, `key_resets_at` and `top_up_url`, where you add credits.

All amounts are US dollars. `null` means no limit.

## Rate limits

Summer limits how fast jobs start for each kind of asset (images, audio, 3D and video). Over the limit, a call answers `429` with a `Retry-After` header in seconds. Wait that long, then send the same request with the same `Idempotency-Key`.

## Keep keys safe

- Keep keys on a server, in your shell environment or in a `.env` file that is in `.gitignore`.
- Never put a key in game code, a game build, a web page or a commit.
- Give each tool or agent its own key with its own limit, so you can revoke one without stopping the rest.
