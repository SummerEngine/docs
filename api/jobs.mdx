Every model runs the same way: one job with a `model` and an `input`. Short jobs finish inside the call. Long jobs, such as a 3D model or a video, give you a job id to follow.

## Know the price first

`POST /v1/estimate` takes the same body as a job and prices it: the exact amount, or the most it can cost when `atMost` is `true`. It is free and needs no key. The answer has these fields at the top level, with no wrapper.

```bash
curl https://www.summerengine.com/v1/estimate \
  -H "Content-Type: application/json" \
  -d '{"model": "3d/default", "input": {"kind": "text-to-3d", "prompt": "a stylized treasure chest, game prop", "rig": true}}'
```

| Field | Meaning |
|---|---|
| `price` | US dollars, as a decimal string |
| `atMost` | `true` when Summer decides a step while the job runs, such as cleaning up a picture first. The charge can be lower, never higher. |
| `breakdown` | What makes up the price: `base`, then each option that adds to it, such as `rig` |
| `quoteId` | Send it with the job: Summer refuses to charge more than this quote |
| `quoteExpiresAt` | The quote holds for 15 minutes |

## Start a job

```bash
curl https://www.summerengine.com/v1/jobs \
  -H "Authorization: Bearer $SUMMER_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Prefer: wait=60" \
  -d '{"model": "3d/default", "input": {"kind": "text-to-3d", "prompt": "a stylized treasure chest, game prop"}, "quoteId": "q_..."}'
```

| Part | Required | Meaning |
|---|---|---|
| `model` | Yes | A model id from [`GET /v1/models`](/api/models), or a default such as `3d/default` |
| `input` | Yes | The model's input. Each model page lists its fields; `inputSchema` in `GET /v1/models/{id}` has the JSON Schema. |
| `quoteId` | No | From `POST /v1/estimate`. If the price went up since the quote, the job does not start and nothing is charged. |
| `Idempotency-Key` header | Yes | A new value for each new job, such as a UUID. Send the same value to retry the same job: you get the first answer, and nothing is charged twice. |
| `Prefer: wait=N` header | No | Hold the answer up to `N` seconds and return the finished job if it finishes in time. Values over 60 count as 60, so give your HTTP client a timeout above 60 seconds. |

The answer is `{"job": {...}}`:

- `201` with `state: "done"`: the job finished. `result` holds the work.
- `202` with `state: "running"`: still working. Follow `job.id`.

The job also carries `model`, the model that ran (also when you sent a default id such as `3d/default`, so you can run the same model again), `estimatedPrice`, and `price` once Summer knows what it charged.

## Follow a job

```bash
curl "https://www.summerengine.com/v1/jobs/$JOB_ID" -H "Authorization: Bearer $SUMMER_API_KEY"
```

Check again after `pollAfterSeconds` when the answer has it, or every 5 seconds. Job ids can hold a colon, such as `gen:...`; send them as they are.

| `state` | Meaning |
|---|---|
| `queued`, `running` | Still working. `progress` (0 to 100) shows how far, when known. |
| `done` | Finished. `result` holds the work. |
| `failed` | It did not work. `error.code` and `error.message` say why. Nothing is charged. |
| `cancelled`, `expired`, `stale`, `declined` | It stopped without a result. Start a new job. |

To get changes pushed instead, open the event stream. It sends a `job` event with `{"job": {...}}` each time the job changes, then `done` with `{"state": ...}` when the job reaches any final state, `failed` included. After about 4 minutes it sends `timeout`: open it again, or check the job.

```bash
curl -N "https://www.summerengine.com/v1/jobs/$JOB_ID/events" -H "Authorization: Bearer $SUMMER_API_KEY"
```

`POST /v1/jobs/{id}/cancel` asks to stop a job. Asset jobs cannot be stopped once they start: the call answers `409` with `unsupported`.

## The result

A finished job's `result` holds Summer file URLs and the ids of the assets in your Summer library:

| Job | `result` |
|---|---|
| Image | `assets`: one entry per image, each with `assetId`, `fileUrl` and `thumbnailUrl` |
| Voice, dialogue, sound, music | `asset`: `assetId`, `fileUrl`, `thumbnailUrl` and `durationSeconds` |
| 3D model, video | `assetId`, `fileUrl` and `thumbnailUrl` of the asset it made |

To read any of them: take every entry of `result.assets`; if there is none, take `result.asset`; if there is none, take `result` itself.

Every URL is on Summer's own storage and downloads without a key. Download the file into your project, or keep the asset id: in Summer Engine your agent imports an asset by its id.

## Send a picture

Image-to-3D, image editing and image-to-video take a public picture URL (`imageUrl`, `referenceImageUrl`). For a file on your computer, upload it first:

<Steps>
  <Step title="Start the upload">
    `POST /v1/files` with an empty JSON body (`{}`) answers with `uploadUrl`, the `fields` to send, `expiresAt`, and `example`: the whole upload as one curl command.
  </Step>
  <Step title="Send the file">
    POST every field as a multipart form field, plus the file as `file`, to `uploadUrl`. PNG, JPEG or WebP.
  </Step>
  <Step title="Finish the upload">
    `POST /v1/files/complete` with three values from the answer to step 2: `public_id` as `publicId`, `version`, and `signature` as `uploadSignature` (not the signature in `fields`). Add `format`: `png`, `jpg`, `jpeg` or `webp`. The answer holds `assetId`, `fileUrl`, `width` and `height`. The picture is a private asset in your Summer library: pass `fileUrl` as `imageUrl`.
  </Step>
</Steps>

The exact fields of each call are in the API reference: [Start a file upload](/api/reference/post-files) and [Finish a file upload](/api/reference/post-files-complete).
