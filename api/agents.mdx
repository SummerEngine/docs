Every agent uses the same API. Coding agents use the `summer` CLI or plain HTTP. Chat apps use the Summer MCP. You approve spending once, with a limit you choose.

## The one step for coding agents

Paste this into **Claude Code, Codex, Cursor, Hermes** or any agent that can run commands:

```text Prompt for your agent wrap
Use the Summer API for game assets (docs: https://docs.summerengine.com/llms.txt). Run `npx -y summer-engine@latest login --api-key` and show me the link it prints. Then run `npx -y summer-engine@latest api run 3d/default --input '{"kind":"text-to-3d","prompt":"a stylized treasure chest, game prop"}' --download assets` and tell me where the GLB is.
```

The agent shows you a link and a code. You open the link, check the code and choose **Allow**. The key is saved on your computer, and the agent makes its first asset.

| Agent | Paste the prompt into |
|---|---|
| Claude Code | the Claude Code chat in your project folder |
| Codex | the Codex chat (CLI or app) in your project folder |
| Cursor | the Agent chat |
| Hermes | the Hermes Agent chat |
| Any other agent | its chat |

## The summer CLI

```bash
npx -y summer-engine@latest login --api-key
```

This opens the Summer Allow page. You check the code, set a spend limit and choose **Allow**. The key is saved to `~/.summer/api-key`; a `SUMMER_API_KEY` in the environment takes its place when set. The command never prints the key. Without a terminal it prints JSON lines, so an agent can show you the `approve_url`.

Then every Summer API call is one command:

| Command | Does |
|---|---|
| `summer api models [id] [--capability 3d]` | Lists models with their input and price. No key needed. |
| `summer api estimate <model> --input '<json>'` | The price of one job and a quote that holds it for 15 minutes. Free. |
| `summer api run <model> --input '<json>' --download [dir]` | Runs the job, follows it and saves each file as `<assetId>.<ext>`. Add `--quote <quoteId>` to cap the charge. |
| `summer api jobs <id> [--wait] [--download [dir]]` | Reads a job, follows it, or saves its files. |

Run them as `npx -y summer-engine@latest api ...`, or as `summer api ...` once the CLI is installed. The output is JSON when piped or with `--json`, and a short summary in a terminal.

The CLI's MCP server has the same calls as tools: `summer_api_key_login`, `summer_api_models`, `summer_api_estimate`, `summer_api_run` and `summer_api_job`.

## Get a key over HTTP

For agents that only make HTTP calls. Three calls, no browser session.

<Steps>
  <Step title="Ask for a key">
    ```bash
    curl -s https://www.summerengine.com/api/api-keys/requests \
      -H "Content-Type: application/json" \
      -d '{"client": "Claude Code"}'
    ```

    Both fields are optional: `client`, the name the person sees (up to 40 letters, digits and spaces), and `limitUsd`, the spend limit to suggest, from 1 to 10000 US dollars (default 5). The person can change the limit on the approval page.

    The answer (`201`) holds `request_id`, `approve_url`, `user_code`, `poll_url`, `poll_token`, `interval` (seconds) and `expires_in` (seconds).
  </Step>
  <Step title="Show the person the link">
    The agent shows `approve_url` and `user_code`. The person opens the link, checks that the page shows the same code, sets the limit and chooses **Allow**.
  </Step>
  <Step title="Poll for the key">
    ```bash
    curl -s "$POLL_URL" -H "Authorization: Bearer $POLL_TOKEN"
    ```

    Poll every `interval` seconds:

    | Answer | Meaning |
    |---|---|
    | `200` `{"status": "pending"}` | The person has not decided yet. Poll again. |
    | `200` `{"status": "approved", "key", "key_id", "limit_usd", "expires_at", "env": "SUMMER_API_KEY"}` | Save `key` right away: it comes back only once. |
    | `200` `{"status": "denied"}` | The person chose Deny. |
    | `410` `{"status": "expired"}` | The request expired. Start a new one. |
    | `409` `{"status": "failed"}` | The account holds its maximum number of keys. The person revokes one, then you start again. |
  </Step>
</Steps>

An agent key spends up to the limit the person approved and lasts 30 days. The person sees it in **Settings > API keys** and can change its limit or revoke it at any time. See [Keys and limits](/api/keys).

## ChatGPT and Claude

Chat apps use the Summer MCP. Add this address as a custom connector and sign in to your Summer account once:

```text
https://mcp.summerengine.com/mcp
```

Then ask in plain words, for example "Make a low-poly pine tree for my game with the Summer API". The agent finds the Summer API operations (`models.list`, `models.estimate`, `models.run`) with `summer_search` and runs them with `summer_call`. Results go to your Summer library. Step by step for each app: [Summer in ChatGPT and Claude](/mcp/chatgpt-and-claude).

Coding agents can add the same server: Claude Code `claude mcp add --transport http summer-cloud https://mcp.summerengine.com/mcp`, Codex `codex mcp add summer-cloud --url https://mcp.summerengine.com/mcp`. It also takes `Authorization: Bearer $SUMMER_API_KEY` instead of a sign-in.

## What agents should always do

- Read models and prices from `summer api models` or `GET /v1/models`, never from memory.
- Price a big batch first with `summer api estimate` or `POST /v1/estimate`, and tell the person the total.
- Send a new `Idempotency-Key` for each new job and the same one when retrying it. The CLI does this for you.
- Save finished files in the project, and keep the asset id to import the asset again.
- Keep the key out of game code, builds and commits.
- On `402`, show the person the error message: it links where to add credits or raise the key's limit.
