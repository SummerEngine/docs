After the store page is filled and the game is exported, your agent uploads the build and publishes. In Studio you do the same under **Check and submit**; see [Publish your game](/build/publish). Every input of these operations: [Store and publishing operations](/mcp/operations/store).

## 1. Upload the build

With the npm MCP on your computer, `summer_publish_build` (operation `store.upload_file`) uploads the file from your disk: a store bundle, a web build or a download. The first call shows what it will upload; the second, with `confirm: true`, uploads it.

```json title="1. Preview"
{ "tool": "summer_publish_build", "gameId": "<gameId>", "clientVersion": "v1.0.0" }
```

It returns the exact game, file, SHA-256, size and version.

```json title="2. Upload"
{ "tool": "summer_publish_build", "gameId": "<gameId>", "clientVersion": "v1.0.0", "confirm": true }
```

| Input | Meaning |
|---|---|
| `gameId` | The store game. Omit it to get the list of your games. |
| `file` | The `.zip`. Defaults to the last `summer_export_game` result. |
| `clientVersion` | `vMAJOR.MINOR.PATCH`. A new upload needs a new version. |
| `platform` | Web builds and downloads: `web`, `macos-universal`, `windows-x64` or `linux-x64`. Defaults to the last export's platform. Omit it for a store bundle. |
| `confirm` | `true` uploads. Without it, the call only shows what it will upload. |
| `publish` | Leave `false`. Publish with `summer_store_publish`. |
| `waitSeconds` | How long to wait for Summer's checks (default 600). On timeout, call again to keep waiting. |

Store bundles upload in 64 MiB parts, web builds in 16 MiB parts. If the connection drops, call it again with the same file and version: it continues the same upload and skips the parts already stored.

Web builds and downloads are **store versions**, one per platform. A web `.zip` is checked before upload: `index.html` at its root, at most 2,000 files and 500 MiB.

<Warning>
  On a game that is already live, a finished web build or download goes live at once. So on a live game only the owner can finish one, in Studio.
</Warning>

**Without the npm MCP** (a hosted agent that has the file elsewhere), run three operations with `summer_call`. They take one `uploadId` for every kind:

1. [`store.upload_begin`](/mcp/operations/store#upload_begin) with `gameId`, `kind` (`bundle`, `web` or `download`) and `sizeBytes`. It returns the `uploadId` and the part plan.
2. [`store.upload_sign_parts`](/mcp/operations/store#upload_sign_parts) with `gameId`, `uploadId` and `parts`. PUT each part to its URL with every returned header.
3. [`store.upload_complete`](/mcp/operations/store#upload_complete) with `gameId` and `uploadId`. It answers a job: wait with `summer_jobs_wait` until it is `done` or `failed`.

## 2. Wait for the checks

`summer_store_status` shows every upload and its state: `uploading`, `processing`, `checking`, `ready` or `failed`. Summer checks a bundle on every platform it lists. A failed upload says what to fix; see [Troubleshooting](/publishing/summer-games-troubleshooting).

## 3. Look at it first (optional)

```json
{ "op": "store.preview_link", "input": { "gameId": "<gameId>", "expires": "1d" } }
```

A private link to the saved page on summer.games. It is hidden from search, and Buy and Play do nothing. It expires after `1h`, `1d` or `7d`.

## 4. Check what is missing

`summer_store_get_listing` returns the publish checklist for each store. Fix everything it lists before you submit. Read it again after each change.

## 5. Publish

`summer_store_publish`:

```json
{
  "gameId": "<gameId>",
  "price": { "currency": "USD", "amountMinor": 0 },
  "note": "First release: desktop and mobile store pages, build v1.0.0.",
  "idempotencyKey": "<a new key>"
}
```

| Input | Meaning |
|---|---|
| `gameId` | The game. |
| `uploadId` | The store bundle to publish (a `b.` id from `summer_store_status`). Defaults to the newest ready one. |
| `price` | The price in US cents: `amountMinor` 50 to 100000, or `0` for free. Omit it to keep the current price. |
| `note` | A short note: what changed and why. |
| `idempotencyKey` | Required. A new key for each new publish; the same key only to retry it. |

It checks the publish checklist first. Then:

- `done`: it went to Summer's review.
- `needs_approval`: give the person `approval.url`, then wait with `summer_jobs_wait` and `job.id`. Nothing is published until they approve. This happens when **Publish** is off in [Agent permissions](/mcp/permissions), and for now on every agent publish: Summer Games still asks the game's owner, and the answer is `needs_approval` with the owner's approval link.

To withdraw a request that still waits: `store.cancel_publish` with `gameId` and the `approvalId`.

## What happens next

1. If an approval link came back, the owner opens it and approves. See [Approvals](/publishing/owner-approval).
2. Summer staff review the page.
3. When the review passes, the game goes live. No second click.

## Updates

Export again with a new version, upload it the same way, and publish again. Players keep the current version until the new one is live.
