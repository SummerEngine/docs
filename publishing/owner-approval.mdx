Your agent asks you first in three cases:

- a switch in **Studio > Settings > [Agent permissions](/mcp/permissions)** is off;
- the change always asks: agent permissions, auto top-up, entering a jam, the analytics event limit;
- Summer Games still asks: for now, you approve price, A/B test and member changes.

Your agent gives you a link. Nothing changes until you approve.

## Approve a request

<Steps>
  <Step title="Open the link">
    Your agent gives you a link like `https://www.summerengine.com/studio/approvals/<id>`. If you have Studio open in a tab, the same request shows there as a card.
  </Step>
  <Step title="Check what will change">
    The request says what your agent wants to do, with each value before and after.
  </Step>
  <Step title="Approve, or turn it down">
    Approve it, and the change happens. Turn it down, and nothing changes.
  </Step>
</Steps>

A request for your own yes expires after 24 hours. A request for a game owner's yes expires after 7 days. **Studio > Settings > Agent activity** lists every request and every change, with Undo for prices, sales, country prices, member roles, team names and the event limit.

## Approve going live

Your agent always asks you before a game goes live. It shows you the plan, the page and the build, and asks in the chat. Only after your yes does it take the game live with `summer_go_live`. The game is live as soon as Summer's automatic checks pass. There is no review to wait for.

When **Publish** is off in your Agent permissions, your agent can't take the game live. Turn it on, or publish the game yourself in Studio.

## When you publish yourself

If you click **Publish** in Studio yourself, that is your yes. There is no extra step: the game goes live as soon as the automatic checks pass. See [Publish your game](/build/publish).

## What the states mean

| State | Your agent sees | Meaning | What to do |
|---|---|---|---|
| **Awaiting owner approval** | `awaiting_approval` | Your agent asked. Nothing is published. | Open the link. |
| **Approved** | `done` | You approved it, and the change ran. | Nothing. |
| **Cancelled** | `cancelled` | You clicked **Not now**, or your agent withdrew it. | Ask your agent again when ready. |
| **Stale** | `stale` | The store page changed after your agent asked. | Ask your agent again, so you approve exactly what will change. |

## What your agent may do

With the default switches, your agent can read your games, edit the draft, upload art and builds, and start builds without asking. These defaults apply now. You can change them soon. Until then, price, A/B test and member changes ask you first. Going live always asks you, in the chat. It asks first before it deletes something for good or contacts people, such as a team invite.

Only you can set up payouts. On a game that is already live, only the owner can finish a web build or download.

Summer checks every agent call. A change Summer Games does not take from an agent yet comes back as `needs_approval` with a link for you.

## For agents

- Before a game goes live, call `summer_go_live` without `confirm`, show the owner the plan and ask. Call it with `confirm: true` only after they say yes. The game is live as soon as Summer's automatic checks pass; there is no review, so never tell the owner to wait for one.
- Any answer `needs_approval`: give the owner `approval.url`, then call `summer_jobs_wait` with `job.id` until it is `done`, `cancelled` or `stale`.
- If the job ends `stale`, read the current state again and ask again.
- `summer_store_status` shows every upload, what players get now, and any waiting request.
