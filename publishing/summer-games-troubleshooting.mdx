Find the message you see, then do what the right column says.

Every Summer MCP error has a `code`, a `message` and one `next` step. Do the `next` step first. The store's own reason is in `error.details.was`. Every code: [How Summer answers](/api-reference/mcp#errors).

## Sign-in

### The store did not accept the sign-in

`Summer Games did not accept this connector sign-in`, HTTP `401`, or the code `not_signed_in` or `forbidden`.

- Reconnect the Summer Engine connector in your agent, or run `npx -y summer-engine@latest login --force` to sign in again.
- Still failing: run `summer login --store --force` to register this computer again.
- `403 agent_access_not_enabled`: the email of your Summer account is not confirmed yet. Open the link Summer sent you, then try again.

### Sign-in never finishes

The local MCP waits for the browser on port 47615, 47616 or 47617. Close the program that holds those ports, then try again.

## Export

| Message | Fix |
|---|---|
| Template missing | Web builds and downloads need export templates. Run `summer_export_templates` with `action: "install"` and the platform. See [Export templates](/publishing/export#export-templates). |
| `templates_not_published` | Templates are on the CDN from Summer Engine 0.7.1. Update Summer Engine, or use the templates that came with it. |
| Compatibility renderer refused | `summer_export_game`'s web template runs Forward+ or Mobile. Switch the renderer in **Project Settings → Rendering → Renderer**, or keep Compatibility, export with Godot's standard Web export and upload the `.zip` in Studio. |
| Android not supported | Android in the store bundle needs Summer Engine 0.7.1 or later. Update Summer Engine. |
| Platform not allowed | A game without a server can use the store bundle only for iPhone and Android. Use a download for Mac and Windows. |
| The export times out | The first export imports every asset. Raise `timeoutSeconds` (up to 7200). |
| Textures look wrong on one platform | Turn on that platform's texture format in **Project Settings → Rendering → Textures**: ETC2/ASTC for iPhone, Android and Mac, S3TC/BPTC for Windows. |
| Game opens to a blank window | Re-export with the current Summer release from the [download page](https://summerengine.com/download), not a development build, then upload and promote the new version. See [Game opens to a blank window](/publishing/release-readiness#game-opens-to-a-blank-window). |
| Text shows as boxes on iPhone | Your game reads a font file that isn't in the pack and falls back to `SystemFont`. Add the file to the summer.games preset's non-resource filter, or import the font, then upload and promote a new version. See [Text shows as boxes on iPhone](/publishing/release-readiness#text-shows-as-boxes-on-iphone). |
| The game could not start (iPhone or Android) | Your `.zip` comes from a Summer version line the app doesn't carry. Update Summer, export again, then upload and promote the new version. See [The game could not start](/publishing/release-readiness#the-game-could-not-start). |

## Upload

| Message | Fix |
|---|---|
| `declaration_mismatch` | The platforms in the bundle differ from the ones you uploaded it for. Export again with the same `targets`. |
| Version already used | Every upload needs a new `clientVersion`, such as `v1.0.1`. |
| Upload stopped halfway | Call `store.upload_file` (`summer_publish_build`) again with the same file and version. It continues. |
| A part URL expired | Call `store.upload_sign_parts` again for that part. Sending a part again is safe. |
| Web build rejected | The `.zip` needs `index.html` at its root, at most 500 MiB, 2,000 files and 200 MiB per file. |
| Only the owner can finish this | On a live game, a web build or download goes live at once, so only the owner finishes it in Studio. |
| Build `failed` | Read the reason in `summer_store_status`, fix it, export with a new version and upload again. |
| `in_progress` | Summer is still checking the upload. Wait `details.retryAfterSeconds`, then call again with the same `idempotencyKey`. |

## Store page

| Message | Fix |
|---|---|
| `conflict`: the store page changed since it was read (`412`) | Read it again with `summer_store_get_listing`, then retry. |
| A page in review cannot change | Wait for review to finish. A published or sent-back page starts a new draft when you edit it. |
| Shape or size wrong | The picture must match the slot's shape within 2% and meet the minimum size. See [Store art](/publishing/store-art). |
| `not_found` (`asset_not_found`) | The asset is not one of yours. Find yours with `summer_assets_search` and `scope: "mine"`. |
| `invalid_input` (`image_unreadable`) | Upload a PNG, JPEG or WebP with `assets.upload_begin`, or use a public `https` image URL. |
| `invalid_input` on `uploadSignature` (`invalid_upload`) | The image upload expired or was not signed for you. Start again with `assets.upload_begin`, and pass the `signature` from the upload's own answer as `uploadSignature`. |
| `not_signed_in` in the npm MCP | Run `npx -y summer-engine@latest login`. `summer whoami` shows who is signed in. |
| Mobile description too long | The mobile description is 120-170 characters. Shorten it after **Same as desktop**. |
| Too many pictures | A page holds at most 20 pictures and videos across both stores. Remove some screenshots. |

## Publish and approval

| Message | Fix |
|---|---|
| Publish lists missing items | Fill what `summer_store_get_listing` lists in its checklist, then publish again with `summer_store_publish`. |
| `invalid_input` on `idempotencyKey` | `store.publish` and `store.release` need an `idempotencyKey`. Send a new one. |
| `idempotency_conflict` | The same `idempotencyKey` was used with a different input. Use a new key. |
| `needs_approval`, or `forbidden` (`owner_approval_required`) | Give the owner the approval link. Nothing changes until they approve. See [Approvals](/publishing/owner-approval). |
| The approval link says **This version changed** | The page changed after the agent asked. Ask your agent to publish again. |
| Set up payouts before this game can have a price | Open **Get paid** in Studio and connect your payout account, or approve it as free. |
| `conflict` (`no_approved_build`) | `store.release` only releases a build that went through `store.publish`. Publish with `summer_store_publish` first. |
| `no_credits` | Add credits at `https://www.summerengine.com/studio/credits` (**Add credits**), or turn on auto top-up in Billing. |
| Only the game owner can approve publishing | Sign in with the account that owns the game. |

## Analytics

| Problem | Fix |
|---|---|
| Events report `unavailable` | Normal under Local Play, in the editor and in the browser. Do not send them again. |
| No events in Grow | Events appear after a short delay, and only from a published build that includes them. |
| `capacity_exceeded` | More than 32 events are waiting. Send fewer; put counts in one event. |
| `analytics_storage_limit_exceeded` | Your game's storage is full. Send fewer event types. |

## Playing in the Summer Games apps

| Problem | Fix |
|---|---|
| The game closes after about a minute with **Play paused** or **That link can't be opened**, and the player is signed out | A Summer service refused the player's sign-in. This is Summer's fault, not your game's. Report it on [Discord](https://discord.gg/summerengine) with your game's name, the app and the time it happened. See [The game closes after about a minute](/publishing/release-readiness#the-game-closes-after-about-a-minute). |

## Online play

| Problem | Fix |
|---|---|
| Every online join fails with `world_start_timeout`, but Local Play works | Your server pack most likely starts your title scene instead of your server scene. Add `summer_authority` to the server preset's **Custom Features**, export a new version and promote it. See [Players can't join online](/publishing/release-readiness#players-cant-join-online). |
| Online joins still fail with `world_start_timeout` after that | Your game may pass a fixed Game ID. Call `Summer.initialize()` with no ID. See [check 6](/publishing/release-readiness#6-your-game-doesnt-hard-code-its-game-id). |

Before each release, run the [release readiness checklist](/publishing/release-readiness).

## Still stuck

Ask on [Discord](https://discord.gg/summerengine) first. Include the tool name, the error code and the request id if there is one. You can also email [support@summerengine.com](mailto:support@summerengine.com) or [founders@summerengine.com](mailto:founders@summerengine.com).
