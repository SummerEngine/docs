Summer checks every upload: the platforms, the packs and the files they name.
Those checks show that your export is well formed. They can't show that a
player who presses **Play online** gets into a game. This page covers what
the upload checks can't see.

Each check is here because a real release failed without it. We add a check
whenever that happens again.

## Before every release

### Games with a server

- [ ] **Your server starts its server scene.** See
      [check 1](#1-your-server-starts-its-server-scene).
- [ ] **Online join works with the version you release.** See
      [check 2](#2-join-online-with-the-version-you-release).

### Games with online play

- [ ] **Players can find online play** without changing a setting, or you
      decided on purpose that they can't. See
      [check 3](#3-players-can-find-online-play).
- [ ] **Online progress is saved by your server**, not only on the player's
      device. See [check 4](#4-your-server-saves-online-progress).
- [ ] **Players can get back to the title** from inside the game. See
      [check 5](#5-players-can-get-back-to-the-title).

### Every game that uses Summer

- [ ] **Your game doesn't hard-code its Game ID.** See
      [check 6](#6-your-game-doesnt-hard-code-its-game-id).
- [ ] **You exported with a released Summer editor, and your scripts compile
      on the Summer that players get.** See
      [check 7](#7-export-with-a-released-summer-editor).
- [ ] **Every file your game reads at run time is in the pack, and text shows
      as letters on iPhone.** See
      [check 8](#8-every-file-your-game-reads-is-in-the-pack).
- [ ] **You exported with the Summer version the Summer Games apps run.** See
      [check 9](#9-export-with-the-summer-version-the-apps-run).

## The checks

Run the checks on the file you upload: your summer.games `.zip`. Export it
as usual, in the editor (**Project → Export**, the **summer.games** preset) or
with your agent, and take the server out of it:

```sh
unzip -o build/my-game.summer.zip server.pck -d build/bundle
```

A server pack you export on its own with your server preset is not the same
file. It can pass a check that the uploaded `.zip` fails.

### 1. Your server starts its server scene

Summer starts your game's server with no scene named. The server pack's own
main scene decides what runs. Your server preset carries the custom feature
`summer_authority`, and `project.godot` sets that feature's main scene to
your server scene:

```ini title="project.godot"
[application]

run/main_scene="res://client/main.tscn"
run/main_scene.summer_client="res://client/main.tscn"
run/main_scene.summer_authority="res://authority/main.tscn"
```

```ini title="export_presets.cfg (your server preset)"
name="Duel Authority"
platform="Linux"
dedicated_server=true
custom_features="summer_authority"
```

If the preset is missing `summer_authority`, the server starts your
**players'** main scene instead, usually the title screen. That scene never
tells Summer the server is ready, so every online join fails.

**Check it.** Start the server from your `.zip` the way Summer does, with no
scene named:

```sh
<summer> --headless --verbose --main-pack build/bundle/server.pck
```

`<summer>` is the Summer Engine executable. Stop it after a few seconds and find the first `Completed load for: 'res://…tscn'` line. It
must be your server scene, such as `res://authority/main.tscn`. If it shows
your title or client scene, add `summer_authority` to the server preset's
**Custom Features** and export again.

Local Play always starts your server scene by name, so a game can work
there and still fail this check.

### 2. Join online with the version you release

The check above runs on your computer. Players use a hosted server, so
also test there: right after you promote a new version, open your game in a
Summer Games app, join online and play until you're in the game. Do it
before you tell players about the update. If the join fails, see
[Players can't join online](#players-cant-join-online).

### 3. Players can find online play

A new player should reach online play without changing a setting. If online
play is off by default, for example behind a grown-ups setting, make that a
deliberate choice. Then join online yourself before every release, because
no player will find it broken for you.

### 4. Your server saves online progress

In online play, your server saves each player's progress with
[player progress](/build/player-progress) and loads it when they join.
Progress kept only on the player's device is lost when they reinstall or
switch device, and players can edit it. To test, play online, earn
something, leave, then join from another device.

### 5. Players can get back to the title

Inside a game, players need a way back to the title screen, such as a pause
menu or a **Leave** button, online and offline. Without one, the only way out
is to close the app.

### 6. Your game doesn't hard-code its Game ID

Start Summer with no Game ID:

```gdscript
var result: SummerResult = await Summer.initialize().get_result_or_completed_signal()
```

Summer then takes your game's identity from wherever the game runs: the
Summer Games app, your hosted server or Local Play. The exported `.zip` is
portable, so its `summer.build.json` has no `gameId`. If your code reads
`gameId` from that file and falls back to a made-up ID such as
`"game.my-game"`, the hosted server refuses it with
`game_identity_mismatch`. Your server then stops before it is ready, and
players' online joins fail. The Summer Games app refuses it the same way.

**Check it.** Search your project for `Summer.initialize`. Every call passes
no ID, or an ID your game received from Summer, never a fixed string or a
fallback. Then join online with the released version (check 2). Local Play
and a local run of `server.pck` don't run under a hosted identity, so they
can't catch this.

### 7. Export with a released Summer editor

Use the released Summer editor from the
[download page](https://summerengine.com/download), not a development build.
After you update Summer, export again before you upload.

Your export records which Summer made it, and players' apps run your game on
the released Summer of that version. A development build can call itself a
version that is already released while it has features that version lacks.
Your scripts then use something that isn't there on players' devices. They
fail to load, and the game opens to an empty window for every player. Summer
doesn't compile your scripts when you upload, so the upload still passes.

**Check it.** Read which Summer made your `.zip`:

```sh
unzip -p build/my-game.summer.zip summer-bundle.json
```

Under `"export"`, `summerVersion` must be a released Summer version, and
`engineSha` must match the `engineSha` that Summer publishes for that version
at `https://downloads.summer.games/engine-templates/<summerVersion>/manifest.json`
(Summer 0.7.1 and later). If it differs, a development build made the export.
If that address has nothing for your version, update Summer and export again.

Then run your game on that released Summer and look for scripts that fail to
load:

```sh
unzip -o build/my-game.summer.zip client.pck -d build/bundle
<summer> --headless --verbose --main-pack build/bundle/client.pck --quit-after 600 2>&1 | grep -E 'SCRIPT ERROR|Parse Error|Failed to load script'
```

`<summer>` is the released Summer Engine executable of that version. The
command must print nothing. Don't rely on the run failing: it finishes
normally even when a script can't load. The run loads your main scene and
autoloads; a script that loads only later in play is checked when you play
to it.

### 8. Every file your game reads is in the pack

Summer packs your scenes, scripts and imported assets for you. A file that
your game opens itself at run time, with `FileAccess` or another call that
reads a `res://` path, is different. If Summer doesn't import the file, for
example a `.bin`, `.json` or `.txt`, it goes into the pack only when your
export preset's **Resources → Filters to export non-resource files/folders**
matches it. Each preset has its own filters, so set them on the
**summer.games** preset that makes your `.zip`. A file the filters leave out
is not an export error: your game just can't find it on players' devices.

Fonts are where this shows first. On iPhone your game can't use the
phone's own fonts, so a `SystemFont` draws every letter as a box there. On
your Mac or PC the same game looks fine, because `SystemFont` finds a font
on your computer.

**Check it.**

1. Search your scripts for files they read by path:

   ```sh
   grep -rn -E 'FileAccess\.|DirAccess\.|load_from_file|load_dynamic_font|ConfigFile' --include='*.gd' .
   ```

   Note every `res://` file or folder those lines read. Skip `user://`
   paths; those are saves.
2. List what is in your pack. Save this script outside your project, for
   example as `list_pack.gd` in your home folder:

   ```gdscript title="list_pack.gd"
   extends SceneTree
   # Prints one "PACK res://..." line per file in the pack.
   func _init() -> void:
       _walk("res://")
       quit()

   func _walk(dir: String) -> void:
       var d := DirAccess.open(dir)
       if d == null:
           return
       d.include_hidden = true
       for f in d.get_files():
           print("PACK ", dir.path_join(f))
       for s in d.get_directories():
           _walk(dir.path_join(s))
   ```

   Then run it on the `client.pck` from your `.zip`:

   ```sh
   unzip -o build/my-game.summer.zip client.pck -d build/bundle
   <summer> --headless --main-pack build/bundle/client.pck --script ~/list_pack.gd | grep '^PACK '
   ```

   Every file from step 1 must have its own `PACK res://…` line. If one is
   missing, add it to the summer.games preset's non-resource filter, for
   example `fonts/*.bin`, export again and check again.
3. Don't use `SystemFont` for text that phone players see, not even as a
   fallback. Put the font in your project: import a `.ttf` or `.otf`, or read
   its bytes from a file that step 2 shows is in the pack. If you need a
   fallback, use `ThemeDB.fallback_font`, Summer's built-in font.
4. Right after you promote the version, open your game on an iPhone in the
   Summer Games app and look at the title screen and one menu. Every label
   must show letters, not boxes. Your editor, Local Play and the desktop app
   can't show this problem.

### 9. Export with the Summer version the apps run

The Summer Games apps for iPhone and Android carry Summer inside them. An
app runs a game exported with the same Summer version line, the first two
numbers such as `0.7`, at the app's patch number or lower. A game exported
with `0.6.x` doesn't start in an app that carries `0.7`, and players see
**The game could not start**. The desktop app gets the right Summer for each
game, so your game can work on Mac and Windows and still fail on every
phone.

**Check it.** Read which Summer made your `.zip`:

```sh
unzip -p build/my-game.summer.zip summer-bundle.json
```

Under `"export"`, the first two numbers of `summerVersion` must match the
current Summer release on the
[download page](https://summerengine.com/download). When Summer moves to a
new version line, for example from 0.6 to 0.7, update Summer, export your
game again, upload it as a new version and promote it. Then open it on a
phone, as in [check 2](#2-join-online-with-the-version-you-release).

## Troubleshooting

### Players can't join online

Every online join waits and then fails with `world_start_timeout`, while the
game works in Local Play.

**Most likely causes:**

- **Your server pack starts the wrong scene.** Run
  [check 1](#1-your-server-starts-its-server-scene). If it loads your title or
  client scene, add `summer_authority` to your server preset's **Custom
  Features**, export a new version, upload it and promote it.
- **Your game passes a fixed Game ID.** Run
  [check 6](#6-your-game-doesnt-hard-code-its-game-id). Call
  `Summer.initialize()` with no ID, export a new version, upload it and
  promote it.

**An empty server log does not mean nothing ran.** A release server holds
back what your game prints when it isn't attached to a terminal. Its output
can look empty even while your title scene is running. Use check 1 on your
own computer to see which scene starts.

If checks 1 and 6 pass and joins still fail, ask on
[Discord](https://discord.gg/summerengine) with your game's name and the time
you tried.

### Game opens to a blank window

Your game opens to an empty or black window for every player, while it works
in your editor. Running your `.zip` as in
[check 7](#7-export-with-a-released-summer-editor) prints lines such as
`Parse Error: Static function "…" not found` and
`Failed to load script "res://…"`.

**Most likely cause:** a development build of Summer exported the game, and
your scripts use something the released version doesn't have. Re-export with
the current Summer release from the
[download page](https://summerengine.com/download), upload the new version
and promote it. Run check 7 on the new `.zip` before you upload it.

### Text shows as boxes on iPhone

Every letter in your game draws as an empty box on iPhone, while it looks
right on your computer. Your game most likely reads a font file that isn't
in your pack and falls back to `SystemFont`. Run
[check 8](#8-every-file-your-game-reads-is-in-the-pack): add the font to the
summer.games preset's non-resource filter, or import it, export a new
version, upload it and promote it.

### The game could not start

The Summer Games app on iPhone or Android says **The game could not start**,
while the game works on desktop. Your `.zip` most likely comes from a Summer
version line the app doesn't carry. Run
[check 9](#9-export-with-the-summer-version-the-apps-run): update Summer,
export again, upload the new version and promote it. If the versions match
and it still fails, ask on [Discord](https://discord.gg/summerengine) with
your game's name and the time you tried.

## Ask your agent

<Prompt description="**Check my game is ready to release.** Your agent runs every check on this page and tells you what fails.">
Check that my Summer game is ready to release. Follow
https://docs.summerengine.com/publishing/release-readiness.md.

- For a game with a server, export the summer.games .zip, take server.pck out
  of it and run it with --main-pack and no scene, as the page shows. Tell me
  which scene it loads first.
- Find every Summer.initialize call and tell me which Game ID it passes.
- Read the export stamp in summer-bundle.json, tell me which Summer version
  and engine made it, and whether that is a released Summer. Run client.pck
  on that released Summer and show me any script that fails to load.
- Find every file my scripts read by path, list client.pck and tell me which
  of those files are missing from it. Tell me if any text uses SystemFont.
- Tell me whether the summerVersion in summer-bundle.json is on the same
  version line as the current Summer release.
- Go through every other check on the page and tell me pass, fail or "I can't
  check this, you need to" for each one.
- Don't change anything until I've seen the list.
</Prompt>
